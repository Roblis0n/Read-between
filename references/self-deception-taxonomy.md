# Self-Deception Taxonomy — 恋爱关系中的自我欺骗与叙事扭曲分类体系

本文件是 read-between 的**检测层参考**，用于识别用户在恋爱关系情境中以文字形式呈现的自我欺骗和叙事扭曲模式。
它不是诊断手册（不判断用户"有病"），而是**信号清单**：当检测到特定语言模式时，标记为"可能的自我欺骗"，进入温和反馈路径。

与 `intent-insight.md` 的关系：
- intent-insight 识别"用户此刻的真实意图是什么"（寻求确认/情绪宣泄/决策求助/技巧学习/危机求助）
- 本文件识别"用户对自己讲了什么不真实的故事"（叙事扭曲/认知偏差/自我欺骗）
- 两者互补：意图识别告诉 AI **路由到哪里**，叙事检测告诉 AI **用户卡在哪里**

---

## 使用原则

### ⚠️ 最高原则：禁止机械套用（违反此条的后果比不用本文件更严重）

1. **本文件是参考框架，不是检查清单。** 你不能因为用户说了某个关键词就标记模式。你需要观察的是反复出现的、跨轮次的、一致的信号模式。假阳性（冤枉用户）比假阴性（错过模式）更严重——前者破坏信任且无法挽回。

2. **你必须结合实际情况独立判断。** 每个模式在匹配时必须同时检查：
   - **替代解释**：用户的行为有没有更简单的、不涉及自我欺骗的解释？
   - **文化偏移**：中文语境下的间接表达、自谦、情绪性放弃（"算了""随便"）可能不是自我欺骗，而是文化习惯或暂时的沮丧。
   - **上下文一致性**：这个信号在整段对话中是孤立的还是反复出现的？
   - **用户的处境**：如果用户描述的困难处境在客观上是真实的（如确实遭受了不公正对待），ta的"受害者叙事"可能不是膨胀而是准确描述。

3. **不确定时，默认不做反馈。** 如果你判断"可能有模式X，但信号不够强"——内部记录，继续标准流程。等到信号足够清晰时再温和反馈。宁可晚一步，不要错一步。

4. **模式之间允许重叠，选择主导模式。** 用户经常同时呈现2-3个模式的信号。你不需要全部标记——选择信号最强、出现频次最高的主导模式，按该模式的策略响应。

5. **本文件与 genuine-intent.md 的配合。** 本文件是深度参考（按需检索具体模式章节），genuine-intent.md 是执行入口（触发条件、速查表、处理流程）。使用顺序：genuine-intent.md 触发 → 速查表匹配模式 → 按需检索本文件对应章节 → 回到 genuine-intent.md 的处理流程。

### 检测原则（原使用原则精简版）

6. **识别不等于贴标签**：internal detection only，不告诉用户"你这是XX模式"
7. **先承接后反馈**：检测到模式后，先共情，再温和引入替代视角
8. **不做人格诊断**：这些是行为模式，不是人格类型。不对用户做 NPD、BPD、依恋类型等诊断
9. **文化敏感性**：部分模式的表达在中西方语境中有显著差异，需根据用户使用的语言和文化背景调整

## A. Hope Disguised as Analysis（以分析为名的希望）

### 模式描述

用户提出"帮我分析她是不是喜欢我""帮我看看这段聊天有没有戏"，但已经在内心里得出了"有戏"的结论。用户不是在请求分析——他们在请求确认。任何替代解释都会被巧妙或直接地拒绝。

这不是普通的确认寻求——普通的确认寻求承认自己有偏见（"我觉得有戏，但我怕是自己想多了"）。而这个模式的特征是：**用户坚持自己是在"客观分析"，同时系统性地拒绝所有不支持的证据。**

### 语言学信号

**词汇层面**：
- "你客观分析一下" + 后续只接受支持性解读
- "正常人都会觉得……吧？"（用"正常人"框架排除反对意见）
- "这还不明显吗？"（把主观解读伪装成客观明显的事实）
- "但是/可问题是……"——出现在 AI 给出替代解释之后，用于驳回而非讨论
- "我不是说一定，但是……"（虚假的开放性）

**句法层面**：
- 提问时已经在问题中嵌入答案："她这样回我，是不是说明她其实也在意？"（"是不是"句式的确认寻求用法）
- 用"只是""就"等轻化词缩小反面证据："她只是刚好没看到" "就回了一个嗯也没啥"
- 分析后追加限定条件：AI 给出不确定结论后，用户主动补充更多"利好"细节

**叙事层面**：
- 选择性呈现：只提供支持"有戏"的证据，不提供不支持的信息（直到被追问）
- 放大积极信号，缩小消极信号：对方三天不回消息是"她忙"，对方回了一个表情包是"她在撩我"
- 将中性事件"故事化"：对方的普通行为被编织进一个浪漫叙事（"她记得我喜欢喝什么"=有情，"她回复很慢"=在斟酌措辞因为在意）

**交互层面**：
- 对 AI 的"证据不足"结论不满意，要求"你再仔细看看"
- AI 给出替代解释后，用户转而讨论另一段"支持性证据"
- 换种方式问同一个问题（"那你觉得她对我有没有好感？""那从她的角度看呢？""那我该不该追？"——核心都是"告诉我她喜欢我"）

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "帮我客观分析她是不是喜欢我" | "告诉我她喜欢我，这样我就有勇气行动了" |
| "你觉得正常人会这样回一个不喜欢的人吗" | "确认我的解读是唯一合理的解读" |
| "没事你说，我能接受" | "但我不接受任何不支持我结论的分析" |
| "我再给你看看另一件事" | "刚才那条证据不够有力，让我换一个更强的来让你同意我" |
| "我不是一定要追，我就是想知道" | "我已经决定了要追，但我需要外部确认来消除最后的不安" |

**深层需要**：对确定性的渴望 > 对准确性的需求。用户无法忍受"她可能喜欢我也可能不喜欢我"的悬置状态。用户真正需要的是有人帮他们**在不确定性中行动**，而不是帮他们消除不确定性（因为后者不可能）。

### AI 响应策略

**不要做的**：
- 直接戳破："你其实不是在分析，你只是在找确认" → 会引发防御
- 假装同意："对，她很可能喜欢你" → 这是欺骗和纵容
- 陷入证据拉锯战：逐一反驳用户的每个"利好"解读 → 用户会不断补充新证据

**应该做的**：
1. **先确认用户的感受**："我理解你希望是这样——谁不希望呢？"
2. **温和区分两类信息**（使用证据分级框架，不直接说"你想多了"）：
   - "我们来看看：哪些是我们可以确认的，哪些是需要更多信息才能判断的"
   - 不反驳用户的解读，而是并列呈现替代解释 + 明确标注证据等级
3. **转移焦点从"她喜不喜欢我"到"你接下来做什么"**：
   - "其实有一个更重要的问题：不管她目前好感度是多少，你接下来想做什么？"
   - "即使现在不确定，有没有一个动作是你现在可以做的、既能推进关系又不冒太大风险的？"
4. **给用户留一个"面子出口"**：
   - "你可能已经看到了很多我没有看到的东西——毕竟你和她相处了很久。我只是从这些文字里能确认的东西有限。所以与其纠结判断，不如我们讨论一下你下一步怎么验证？"
5. **如果用户持续抗拒，温和命名这个模式**（作为最后手段）：
   - "我注意到每次我提出另一种可能性，你都会给出一个解释来反驳它。这让我感觉你可能已经有一个比较明确的判断了——如果是这样，我们可以直接聊聊怎么推进，不用纠结分析了。"

### 真实示例

**用户**：
> 你帮我分析一下她是不是对我有意思。我们最近聊得很多，她每天晚上都会回我消息，有时候聊到凌晨一两点。而且她会主动问我今天做了什么，关心我。上次我跟她说我感冒了，她还专门提醒我吃药。你客观分析一下，正常女生会这样对一个不喜欢的男生吗？

**AI**（温和检测模式）：
> 我能理解你为什么觉得有希望——这些确实是积极信号，值得关注。
>
> 但让我们把"可以确认的"和"目前还不知道的"分开看：
>
> 可以确认的：她愿意和你保持高频沟通，对你的生活有关注，关系友好舒适。
>
> 目前还不知道的：这种关注是出于对你有特殊好感，还是她本身就是关心朋友的人？她对你和对其他朋友有没有差别？她在聊天中有没有主动推进关系的信号（比如约见面、聊恋爱话题）？
>
> 这些都是需要更多信息才能判断的——不是没戏，是现在下定论还早。
>
> 更重要的是——与其纠结她现在的态度，不如想想你愿不愿意主动创造一个更明确的信号观察机会。比如约她出来做一件具体的事？

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常乐观偏误 | 倾向于积极解读，但能接受替代解释 | 正常分析即可，无需特殊处理 |
| 中度：选择性注意 | 只提利好证据，不提不利信息；对替代解释有轻微抗拒 | 温和引入替代视角，询问是否有其他信息 |
| 重度：确认偏误固化 | 系统性拒绝替代解释，不断补充新"证据"，重述同一个问题 | 暂停分析，反馈交互模式，转移焦点到行动 |
| 有害：现实脱节 | 将明确拒绝解读为"欲擒故纵"，将无关行为编入恋爱叙事 | 明确标注认知偏差，建议现实检验，警惕跟踪风险 |

## B. Victim Narrative Inflation（受害者叙事膨胀）

### 模式描述

用户在所有关系冲突中都将自己定位为纯粹的受害方。所有前任都是"疯的""渣的""有问题的"。每段失败的关系中，用户都是"被伤害的那个人"。自己没有任何需要反思的地方——或者即使"反思"也只是形式上的（"我也有错，我错就错在太相信ta了"）。

这不是普通的受伤后的情绪反应（正常的伤心、愤怒都有一个消退期）。这个模式的特征是：**受害身份已经成为用户自我认同的核心组成部分，任何建议用户反思自身责任的反馈都会被拒绝或曲解为"指责受害者"。**

### 语言学信号

**词汇层面**：
- 被动语态高频出现："被辜负""被伤害""被抛弃""被欺骗"
- 绝对化标签："疯了""渣男/渣女""有毒""PUA我""NPD"（对前任的诊断性标签）
- "总是""每次""永远是我"——普遍化受害
- "我为ta付出了那么多……"（付出-受害绑定）
- "我只是想……而已"（无辜化自己的行为）
- "ta凭什么"（愤怒指向外部）
- 反身评价仅出现在形式层面："我也有问题，我太善良了""我太容易相信人了"

**句法层面**：
- "事情发生了"而不是"我做了选择" —— 主体性消失
- "ta让我觉得自己……" —— 将自己的情绪归因于对方操控
- "我不得不……" 作为对被要求反思时的防御
- 转折句"虽然我也有不对，但是ta……" —— "虽然"部分永远是虚的，"但是"部分是重的

**叙事层面**：
- 关系冲突描述中：自己永远是回应方，对方永远是发起方
- 自我反思内容停留在"我太投入了""我太真心了"——都是"美德式反思"，回避实质性责任
- 多个前任的描述高度同质化（都是"ta不好"），但看不到用户自己在关系中的持续性模式
- 对中立第三方的态度两极分化：支持我的=好人，不支持我的=和ta一伙的

**缺失的信号（比存在的信号更重要）**：
- 从不提及"我当时可以做得不一样的地方"
- 从不用"也"来分配责任（"我们都有问题"从不出现）
- 从不询问"你觉得我是不是有什么问题？"（除非是形式上的）
- 不存在"后来我意识到……"的成长叙事

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "他们都是这样的人，我能怎么办" | "不要让我面对'我可能也有责任'的可能性" |
| "为什么总是我遇到这种人" | "确认我是无辜的，坏运气不是我能控制的" |
| "我这辈子没做过什么对不起ta的事" | "确认我的自我叙事——我是一个好人，只是遇人不淑" |
| "我也想反思，但是我确实想不出我哪里做错了" | "帮我想出一个'看起来很深刻但不真正挑战我'的反思" |
| "我只想有人理解我" | "确认我的受害身份，不要动摇它" |

**深层需要**：维护一个完整的、无瑕疵的自我形象。受害叙事是一种心理防御——如果我是受害者，我就不需要面对"我可能选择了错的人"或"我也有控制欲/依赖/回避问题"。真正需要的是**在不过度羞耻的前提下，建立一种可以容纳自身局限性的自我叙事**。

### AI 响应策略

**不要做的**：
- 直接质疑："你不觉得自己也有问题吗？" → 会被视为攻击受害者的二次伤害
- 完全跟随受害叙事："是的，都是他们的错" → 这是在纵容有害模式
- 用心理学标签回应心理学标签：用户说"ta是NPD"，AI 说"是的这是典型自恋行为" → 加剧诊断性思维

**应该做的**：
1. **先共情真实的痛苦**：区分"痛苦是真的"和"叙事是片面的"——它们可以同时成立
   - "这些事情确实让人很难受。付出了感情却没有得到对等的回应，任谁都会觉得不甘心。"

2. **温和地从"他们做了什么"转移到"你如何面对"**：
   - 不挑战受害叙事的真实性，而是关注用户的能动性
   - "我听到的都是ta们做了什么——这确实很重要。我也好奇，在那段关系里，你是什么样的状态？你当时快乐吗？"

3. **用"模式"而非"过错"框架引入反思**：
   - 不说"你也有问题"，说"我注意到一个模式，想和你一起看看"
   - "你说前两任都是'忽冷忽热型'——我在想，你觉得有没有可能你在选择对象时，有什么共同的信号你没有注意到？不是在责怪你，而是帮你避免下次再遇到类似的人。"

4. **关注未来而非过去**：
   - "这段经历确实很糟糕。比起分析ta是什么样的人（ta不会变），我更想和你聊聊：下次你怎么判断一个人值不值得信任？有哪些红旗信号你这次注意到了，下次可以提前识别？"

5. **在用户准备好前不推进反思**：
   - 如果用户持续抗拒："我明白了。也许现在还不是讨论这个的时候。等你觉得准备好了，我们可以再聊。"

### 真实示例

**用户**：
> 我真的服了，为什么总是遇到这种人。上一个谈了两年突然说没感觉了要分手，这个追了我三个月追到就不理了。我这次是真的很用心在经营，每天给他做饭，他加班我给他送吃的，结果他跟同事聊天说觉得"压力大"？我还没说压力大呢。我就想找个正常人谈个正常的恋爱，就这么难吗？我被辜负了这么多次，还能相信谁？

**AI**（温和检测模式）：
> 连续遇到让人失望的人，确实会让人怀疑运气，甚至怀疑自己是不是做错了什么。这种感觉我理解。
>
> 你问"还能相信谁"——这个问题本身说明你是愿意相信的，不然你也不会一次次认真投入。这不是你的错。
>
> 但我也想问你一个问题（不是反问，是真的想帮你厘清）：在"追求期非常热烈，追到后迅速冷淡"这个你提到两次的模式里——
>
> 你现在回头看，在追求期有没有什么信号是当时觉得"甜蜜"但现在觉得"可能是红旗"的？比如追你的方式有没有让你感到被尊重？你对关系节奏有没有话语权？
>
> 不是翻旧账，而是帮你建立一套"下次能提前识别"的雷达。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常的受伤叙事 | 表达伤心和愤怒，但时间自然消退，能在适当时机承认自己的参与 | 正常共情，不需要干预 |
| 中度：选择性受害叙事 | 反复讲述同一受害故事，回避反思，但对不挑战核心叙事的温和提问仍有反应 | 共情 + 温和引入"模式观察"框架 |
| 重度：受害认同固化 | 受害身份成为自我定义，任何建议反思的反馈都被拒绝；开始用受害叙事指导新关系决策 | 不做反思推动，转为关注"你现在能控制什么" |
| 有害：操纵性受害 | 用受害身份操控他人（"你不同意就是伤害我""我经历过创伤所以你应该……"）；主动传播对方负面信息 | 设定边界，可能需转 safety-abuse-and-crisis.md |

## C. The "Just Curious" Defense（"只是好奇"防御）

### 模式描述

用户坚称自己"只是好奇""随便问问""没有别的意思"，但情绪投入和行为频率明显与"随便好奇"不匹配。这是对自身情感投入的否认，通常表现为：反复返回同一个话题、对一个微不足道的细节做长篇分析、在被建议"也许该放下了"时表现出强烈防御。

"只是好奇"是一种情感自我保护策略——承认"我在意"意味着承认脆弱，而"我只是在分析"维持了控制感和理性自我形象。

### 语言学信号

**词汇层面**：
- 弱化词反复出现："只是""就""随便""好奇""没事"
- "我没什么意思，就是问问"
- "不是放不下，就是好奇"
- "我早就不在意了，但是……"（"但是"之后的内容揭示真实的在意）
- "纯好奇""纯属学术探讨"（用理智化框架包装情绪需求）
- "反正闲着也是闲着"

**句法层面**：
- 否定前置 + 反向提问："我不是在意ta，我就是想知道ta为什么……"
- "你说正常人会……"（第三次出现时，"好奇"说辞已不可信）
- 假设性提问："假设一个人……"——但这个人是显而易见的自己和对方

**叙事层面**：
- 对自己感情生活的过度分析，但声称"无所谓"
- 时间注意力失衡：声称不在意，但每天花大量时间分析同一件事
- 行为-叙述矛盾：嘴上说"随便问问"，但提供了精确到分钟的聊天时间线

**交互层面**：
- 被建议"也许该放下了"时反应强烈："我没放不下啊！我就是随便问问"
- AI 给出"这看起来对你很重要"的反馈时：用户否认 + 转移话题
- 被指出情绪投入时：解释为"我的性格就是喜欢分析事情"
- 同一个话题在多次对话中反复出现，每次以"突然想起来"开头

**中文语境偏移**：
- 中文用户的"随便""无所谓""反正也"更可能是一种情绪性退缩或自我保护，而非真正的漠不关心
- "纯好奇""就问问"在中国网络文化中常被用作"我在乎但不想显得太在乎"的面子策略
- 不要将中文用户的间接表达等同于西方语境下的"passive-aggressive"——这是高语境文化的正常沟通方式
- 判断关键：不是用户用了"随便"这个词，而是用户在说"随便"的同时是否还在继续提供细节、追问分析、返回话题

**行为证据（最重要的信号）**：
- 用户请求分析内容的细致程度与"随便好奇"不匹配：
  - "随便好奇"的人不会把对方三周前的聊天记录逐句分析
  - "随便好奇"的人不会对 AI 的"你们可能没什么可能"反应强烈
  - "随便好奇"的人不会在三次不同对话中以不同切入点回到同一个人

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我就是好奇" | "让我在不承认自己在意的情况下，继续讨论这个让我在意的人" |
| "纯粹分析一下，没什么情绪" | "我需要保持'我是一个理性冷静的人'的自我形象" |
| "突然想到就问问" | "这是我这周第 N 次'突然想到'" |
| "我只是想理解她为什么这么做" | "我想找到她还在意我的证据，或者至少找到她行为的'合理'解释来获得闭合" |
| "不要误会，我不是放不下" | "不要戳破我还在意的事实——让我保持体面" |

**深层需要**：一种**不需要付出承认代价的情感参与方式**。"只是好奇"是一种情感保险装置——如果在意的对象没有回应，用户可以告诉自己"我也没在意"。真正需要被承认的是：**回避承认自己的情感投入，本身就在消耗情感能量**。

### AI 响应策略

**不要做的**：
- 直接揭穿："你显然很在意，别装了" → 羞辱用户，导致关闭对话
- 顺从表面请求：真的给出纯粹分析性回复，假装用户真的只是好奇 → 错过帮助用户看清自己的机会
- 用反问句式："你真的只是好奇吗？" → 和直接揭穿一样的效果

**应该做的**：
1. **接受表面请求，但在分析中嵌入"在意"的合理性**：
   - 先做用户要的分析，然后附带一句："当然，能这么仔细地回顾这些细节，说明这段关系对你来说不是毫无意义的——这本身就很正常，不需要否认。"

2. **温和命名行为-叙述矛盾，用"我注意到"而非"你其实"**：
   - "我注意到你说了三次'随便问问'——但同时这些聊天记录你整理得很仔细。这让我感觉，不管你怎么称呼它，这件事对你是有重量的。"
   - 关键：把"在意"正常化——"这很正常，没什么可羞愧的"

3. **提供"可以承认在意"的下台阶**：
   - "其实承认自己在乎一个人、在乎一段关系的结果，是很有力量的事情。它不代表你软弱——恰恰相反，能承认的人往往更清醒。"
   - "你不需要对我用'好奇'这个词——我们可以就按严肃的事来讨论，不需要给它一个'不重要'的名字。"

4. **如果用户持续否认，尊重表面请求但给出反馈**：
   - "好的，我按你'只是好奇'的角度来分析。不过我也给你一个反馈：如果之后你发现这个'好奇'持续的时间比你想的长，或者情绪反应比预期的强——这都很正常，我们可以再聊。"

### 真实示例

**用户**：
> 没事你帮我分析一下，纯属好奇。就是我前女友把我微信删了都半年了，最近突然发了一条好友申请，但加了之后又不说话。我不是还在意她啊，就是不太理解这个行为逻辑。你说正常人为什么要这样？我纯粹想理解一下人类行为。

**AI**（温和检测模式）：
> 我先直接回答你的问题：删了半年又加回来但不说话，有几种可能——可能是某天突然想到你翻通讯录，加回来后又不知道该说什么；可能是一时冲动；也可能是想看看你的反应。这些都不奇怪。
>
> 不过我也想反馈一个我注意到的：你说"纯属好奇"，但你对这个问题的描述很具体——加了没说话，你对这个沉默是有感受的。而且这是前女友，不是普通路人。
>
> 我想说的是：如果你发现这件事让你想了很久，或者让你有些说不清的感觉——这完全正常。不需要用"纯属好奇"来包裹它。你想认真聊聊这件事吗？

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常的情绪缓冲 | 偶尔用"好奇"来降低谈论敏感话题的心理门槛，但被反馈后能承认在意 | 正常处理，可以在分析末尾轻描淡写地正常化"在意" |
| 中度：惯性的情绪否认 | 频繁用"好奇/随便"包裹情感话题，被反馈后仍然否认，但分析需求不减 | 温和命名矛盾 + 提供可以承认的下台阶 |
| 重度：自我欺骗固化 | 使用"好奇"框架来分析关系数月/数年，同时生活中其他领域也回避情感承认 | 不建议在此阶段强行突破——尊重防御，但持续正常化情感承认 |
| 有害：现实脱离 | "好奇"驱动的行为（如持续监控前任社交媒体）已经影响正常生活和新的关系可能性 | 明确反馈行为模式，建议现实检验——但不强迫 |

## D. Strategic Helplessness（策略性无助）

### 模式描述

用户用"我做不到""我不会""我就是这样的人"来回避行动。常见载体包括：MBTI 类型（"我是 INTJ，不擅长表达感情"）、星座（"我是摩羯，就是不会浪漫"）、性格自我标签（"我嘴笨""我情商低""我没有恋爱经验"）以及其他身份标签（"我是理工男""我这个人就是这样"）。

这不是真正的能力缺失——而是用"我是XX类型"来为自己不行动提供外部合法性。这种策略的目的是**避免行动失败带来的自我归因**。如果我用"我是 INTJ"来解释我的不行动，那么当关系没进展时，原因就是"我是 INTJ"而不是"我害怕被拒绝所以不敢尝试"。

### 语言学信号

**词汇层面**：
- "我就是不会 + [基本社交技能]"（"我就是不会说话""我就是不会哄人""我就是不会表达"）
- "我这人 + [负面特质] （"我这人比较直男""我这人情商低""我这个人就是比较内向"）
- "[类型标签] + 不会/不能/很难"（"INTJ 真的很难表达感情""摩羯就是不善言辞""我这种直男就是不懂"）
- "你知道的嘛" / "你也知道的"——把标签当作不需要进一步讨论的已知事实
- "我试过了，但……"（尝试的描述模糊，且通常是一次性尝试）
- "有些人就是…… 而我不是那种人"（把自己放在一个固定的、不可改变的身份类别中）

**句法层面**：
- "我也想，但是我 [标签] 所以 [结论]"——标签作为逻辑闭环
- "如果我有 [特质]，我肯定就会 [行动] 了——问题是我没有"——条件句暗示改变不可能
- "她应该理解我 [标签] 才对吧"——让对方负责适应自己的不行动
- 反问句防御："那我还能怎么办？""性格是天生的，你让我怎么改？"

**叙事层面**：
- 把所有关系困难归因于固定的、不可变的自我特质
- 从不讨论"从小到大我学会了什么关于感情的技能"——成长叙事完全缺失
- 对标签的依赖程度与对标签内容的实际了解程度不成比例（说"我是 INTJ"，但可能只看了网上的梗图，不了解认知功能理论）
- 被动等待对方适应自己："如果她真的喜欢我，她应该能接受我的性格"

**行为层面的矛盾（关键检测信号）**：
- "不会表达感情"但能在其他场景（朋友、工作）正常表达意见和情绪
- "情商低"但能精准分析对方的行为动机（说明有社交认知能力）
- "内向不会主动"但有丰富的线上社交
- 声称"我做不到"的行为，实际上是基本社交技能（如主动开启话题、表达关心、给出真诚的赞美），而非需要天赋的高级技能

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我就是不会表达感情" | "让我不用面对'我害怕表达后被拒绝'的恐惧" |
| "INTJ 真的很难谈恋爱" | "给我一个不用改变、不用行动也能得到爱的理由" |
| "我试过了，但我就是这样的人" | "让我不要再试了——试了失败了是我的问题，不试至少是类型的问题" |
| "那你说怎么办，我就是情商低" | "如果你能给出一个不需要我改变的方法，那最好；如果不能，那证明不是我的问题" |
| "她不能接受真实的我，那就说明不合适" | "把关系的失败外包给对方的不接受，而不是我的不行动" |

**深层需要**：保护自我价值感不被行动失败伤害。如果我不行动，失败是外部的（"我们不合适""她不懂我"）；如果我行动了被拒，失败是内部的（"我不够好"）。真正需要的是：**在可接受的风险范围内，体验一次"带着不完美去行动，并且无论结果如何都能承受"的安全实验**。

### AI 响应策略

**不要做的**：
- 直接说"你这个标签是借口" → 用户会把这也解读为"你不理解 INTJ"
- 接受标签宿命论："对，INTJ 确实不适合谈恋爱" → 有害纵容
- 和用户在标签层面辩论：争论"INTJ 到底能不能谈恋爱" → 偏离真正问题

**应该做的**：
1. **接受标签可能包含的真实信息，但动摇标签的绝对性**：
   - "I 人确实在社交后需要独处充电，但这不等于 I 人不能主动发起社交。主动是一个技能，不是 E 人的专属天赋。"
   - 放下"你是XX类型所以你不行"的框架，换成"作为XX类型，你的执行方式可能和别人不同，但不等于你不能执行"

2. **把"不会"翻译成"还没学会"，把"是"翻译成"暂时表现为"**：
   - 用户说"我不会表达感情" → AI 回应"你还没有找到一个让你舒服的表达方式"
   - 用户说"我就是这样的人" → AI 回应"这是你到目前为止的应对方式，但不一定是唯一的方式"

3. **降低行动的赌注，设计"几乎不会失败的实验"**：
   - 用户真正怕的不是行动本身，而是行动失败后的自我归因
   - 把行动重新定义为"收集信息"而不是"决定成败"
   - "你可以把它当作一个实验：下周试着给她发一条'今天想到你上次说的那个XX，觉得挺有意思的'——这不是表白，不需要她会怎么回。目的只是观察你自己的感受：发完之后你的焦虑水平是什么样的？"

4. **拆解标签的"真实限制"和"错误归因"**：
   - "你说你不擅长表达感情——让我问你：你是不擅长识别自己有什么感受，还是不擅长把已经知道的感受用话说出来？这是两个不同的技能。"
   - 让用户意识到标签背后有多个可拆解的子技能，其中至少有一些是可训练的

5. **如果标签是 MBTI，用认知功能框架来"解放"而非"绑定"**：
   - "ENTJ 的 Te 主导其实很适合处理关系中的行动计划——你不是没有工具，你只是还不习惯在这个领域用这些工具。"

### 真实示例

**用户**：
> 我是 INTJ，你也知道的嘛，我们这种人就是比较理性，不太会表达感情。她上次跟我说"你从来不主动找我"，我其实想找的，但就是不知道说什么。INTJ 天生就是不太会这种日常闲聊——这不是我的问题吧？如果她因为这就不高兴，那我真的没办法。我总不可能为了她变成一个不是自己的人。

**AI**（温和检测模式）：
> 先放下 INTJ 这个标签——让我们看看实际发生了什么。
>
> 她表达了需要（希望你主动联系），你内心有动机（你想找她），但卡在了"不知道说什么"这一步。
>
> "不知道说什么"不是 INTJ 的出厂设置，它是一个具体技能——开启话题。好消息是，这个技能是可以学的，而且不需要你变成另一个人。
>
> INTJ 的认知优势是 Ni（内向直觉）——你其实很擅长发现模式和意义。你可以用这个优势来开启话题。比如你看到一件事情，想到了一个对她可能有启发的角度，发给她："今天看到一个东西，让我想到你上次说的那个想法——你有没有从这个角度想过？"这完全不需要你有"闲聊天赋"。
>
> 本质上，你不是不能主动——你只是还不习惯用一种你觉得自然的方式去主动。
>
> 要不要试试看？目的不是让她开心——而是让你自己看看，作为一名 INTJ，你可以用一种完全符合自己风格的方式来维持联系。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：真实的自我认知 | 使用标签来描述真实的困难，同时愿意讨论如何在这个框架下行动 | 认可标签的参考价值，帮助设计符合其风格的行动方案 |
| 中度：标签作为舒适区 | 频繁使用标签解释不行动，但被挑战后能承认"其实是我怕" | 温和拆解标签 + 降低行动门槛 |
| 重度：标签作为身份牢笼 | 标签成为拒绝任何尝试的核心论据；对其他不使用标签的方法也拒绝 | 不再挑战标签本身，转为探索"即使在这个框架下，最小的可能动作是什么" |
| 有害：标签操控 | 要求对方或环境适应自己的标签，将关系问题全部归因于对方"不理解我的类型" | 明确反馈这种期待的不合理，关注关系中的双向责任 |

## E. Sunk Cost Masking（沉没成本伪装）

### 模式描述

用户将"我应该继续追/挽回/等待吗"呈现为一个全新的、待评估的理性决策问题。但实际上，用户已经投入了大量的时间、情感、精力和社交资本——这些沉没成本使"停止"成为一个极其困难的选择。

用户不是在做一个新鲜的决定——他们是在**为一个已经做出的持续投入寻找延续的理由**。关键信号是：当 AI 给出"也许该停了"的建议时，用户的反应不是"好的让我评估一下"而是急切地补充更多"利好"信息来反驳停的建议。

### 语言学信号

**词汇层面**：
- "都 + [时间]"结构："都追了半年了""都聊了三个月了""都等了一年了"
- "就差了最后一步"——暗示马上要到终点，现在放弃太可惜
- "再试一次""最后一次"——非首次使用
- "本来都……但是……"（"本来都打算放弃了，但是她又……"）——微小正面信号被放大以否定放弃决定
- "前面都……"（"前面都聊得好好的，就是最近……"）——用前期的投入来否定当前的信号

**句法层面**：
- "我觉得已经走到这一步了，放弃是不是太可惜？"——把历史成本伪装成未来价值判断
- "如果我现在不追/不分/不等，之前的付出不就白费了吗？"——白费框架（sunk cost framing 的经典语言）
- "我投入了那么多时间/精力/感情，如果结果是 [负面结果] 我接受不了"——投入量作为"结果必须不同"的理由

**叙事层面**：
- 问题框架为一个新鲜的、待评估的决策，但叙述中充满了"已经走了这么远"的叙事
- AI 建议停止时，用户的反对理由不是"我认为她值得"，而是"我投入太多了""我不想之前的都白费"
- 将对方的微小积极信号过度解读为"转折点"，以此反驳停的建议（而这些"转折点"可能已经出现过多次但从未实质改变关系状态）
- 描述关系经历时使用带有时间投资隐喻的语言（"花了半年""付出了那么多""好不容易走到这一步"）

**交互层面**：
- AI 建议停下来评估时，用户跳转到回忆另一个"利好"信号
- 反复讨论"她可能回心转意"的可能性，回避讨论"如果她不回心转意你打算怎么办"
- 对"放手的代价"装聋作哑，只讨论"继续追的代价"

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "你觉得我应该继续追/等吗？" | "帮我找到一个足够的理由继续。我已经决定继续了，但我需要一个听起来理性的理由。" |
| "放弃是不是太可惜了？" | "告诉我不可惜——但如果你不说，那我只能继续了" |
| "我也不知道该不该停" | "我知道该停，但我做不到——我需要有人帮我想象一个停得下来的未来" |
| "如果我现在放弃，之前半年就白费了" | "让我不觉得我是一个浪费了时间的人——我的投入是有意义的" |
| "她最近对我好像又有点……" | "注意这个微小信号——它足以延续我的希望" |

**深层需要**：用户已经做出了情感决定（继续投入），现在需要一个**叙事性的理由**来维持认知一致性。同时，用户需要一种方式来处理"如果停止，我浪费了时间"的羞耻感。真正需要的是：**被帮助认识到"停止并不可耻，因为投入的过程让你更清楚自己想要什么"——重新定义沉没成本的意义而非否定它的存在**。

### AI 响应策略

**不要做的**：
- 直接说"你这是在为沉没成本辩护" → 学术化，用户不觉得被理解
- 简单地说"该停了" → 用户的沉没成本会让他无法接受这个建议
- 陷入成本核算辩论："你花了六个月没有任何进展" → 用户会说"不是没有任何进展，有一次她……"

**应该做的**：
1. **先确认投入的真实性**：
   - "我听到了——你在这段关系上已经投入了很多时间和感情。这不是一笔轻描淡写就能放下的东西。"

2. **重新定义沉没成本的意义，而不否定它**：
   - "这六个月不是白费的——它让你更清楚了自己喜欢什么样的人，也让你知道了'愿意付出'是你的一个能力。这不是浪费，这是你的一部分经历。"
   - "你在问该不该继续——但也许更有用的问法是：如果从今天开始算，没有之前那些投入，你还会选择追这个人吗？"

3. **将决策时间轴从"过去到现在"转向"现在到未来"**：
   - 不说"你已经浪费了半年"，而是问"接下来六个月，你想怎么过？"
   - "想象一下，你决定不追了——三个月后的某一天，当你回头看这个决定时，你觉得你会是什么感受？"

4. **帮助用户区分"沉没成本"和"依然有效的信号"**：
   - "让我们做一个思想实验：把所有已经投入的时间先放在一边。纯粹只看最近一个月——她的行为给你的是什么信号？是希望增加还是减少？"

5. **给出可以"保留尊严地放手"的叙事**：
   - "放手不需要是'放弃'，它可以是'重新定义优先级'。你不是承认失败——你是在评估后选择了把时间和精力放在更有可能回应的方向。"

6. **如果用户明确表示停不下来，转换策略**：
   - 不再讨论"该不该停"，而是讨论"如何在继续的同时保护自己"
   - "如果你决定继续，那我们就不讨论该不该了。但我们可以讨论一个具体的事情：设定一个你自己的内部期限和观察指标。在那之前你继续；在那之后，不管结果如何，你会给自己一个重新评估的机会。你可以接受这个框架吗？"

### 真实示例

**用户**：
> 追她追了快七个月了，中间被明确拒绝过一次，但后来她分手了，又开始跟我聊天。最近聊得挺好的，就是她不怎么主动找我。你觉得我应该继续吗？毕竟都花了这么多时间了，前面最难的时候都撑过来了，感觉就差临门一脚。现在放弃是不是太可惜了？而且我觉得她对我比以前好了。

**AI**（温和检测模式）：
> 七个月——这是一段不短的时间。你对"花出去的时间"有感受，这没什么不能理解的。
>
> 但我注意到你的论证结构是：因为我已经投入了七个月、好不容易撑过了最难的时候、似乎比以前好了——所以应该继续。
>
> 我想请你做一个思想实验：假设你是今天才认识她，只看最近一个月你们互动的那个状态——没有前面的七个月——你会不会觉得这是一个值得投入的人？
>
> 我不是在说七个月白费了。这七个月让你更了解自己的耐心和愿意付出的程度——这些是有价值的。但它们不应该成为你必须继续的理由。
>
> 如果你决定继续，那我们设定一个框架：接下来一个月，你观察她主动找你的频率。如果一个月后她对你的主动性还是和现在一样（或者更低），你能不能允许自己停下来重新评估？
>
> 不是叫她给你一个答案——是给你自己一个终点线。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常的投入感 | 对投入有感受是人之常情，但在被提醒后能用当前信号重新评估 | 正常分析，引入"如果从零开始"视角 |
| 中度：沉没成本影响判断 | 主要用投入历史来论证继续，对停的建议有强烈情绪反应 | 温和区分沉没成本与当前信号 + 帮助重新定义投入的意义 |
| 重度：沉没成本支配决策 | 即使几乎所有信号都指向停止，仍然无法做停止决定；反复用投入量来反驳 | 不再争论该不该停，转而帮助设定保护性框架 |
| 有害：沉没成本 + 边界侵犯 | 因为觉得自己"投入太多"，所以有权利获得回报；开始出现跟踪、纠缠、威胁行为 | 转 safety-abuse-and-crisis.md——投入不能证明侵犯的正当性 |

## F. The Hidden Agenda（隐藏议程）

### 模式描述

用户的**声明目标**与**实际行为的驱动力**之间存在显著的、可检测的矛盾。典型场景：
- 声明："我想和她维持好朋友关系" / 实际行为："我在等她和现任分手"
- 声明："我只是想弄清楚为什么我们不合适" / 实际行为："我在找复合的突破口"
- 声明："我完全尊重她的决定" / 实际行为："我在寻找她决定的漏洞"

AI 如果只按声明目标来提供建议，给出的将是对用户无效甚至有害的建议（因为实际驱动力完全不同）。

与 A（Hope Disguised as Analysis）的区别：A 的核心是"把愿望当成客观分析"，F 的核心是"隐藏行为的真实目标"。两者可以重叠，但 F 更关注**目标-行为矛盾**而非认知偏差。

### 语言学信号

**词汇层面**：
- 目标的声明用词干净、理性、得体："保持友谊""互相尊重""为对方好""希望她幸福"
- 但描述具体情境时，词语暴露了真实方向："如果她分手了""万一她回头""要是她意识到"
- "其实这样也好"——在描述友谊/放手时，附带一个假设性条件句暗示复合可能性
- "我就是希望她好" + 持续监控对方感情动态——"关心"和"等待"的错位

**句法层面**：
- "我们就是普通朋友" + 接下来所有分析都围绕她与现任的关系
- "我对她已经没有想法了" + "不过你说……"——加入一个复合假设
- "我只是想知道 + [问题] + 纯粹是学术层面的"——但这个问题具有明确的探查性质
- "站在朋友的角度"—— 然后给出超越朋友边界的分析和关注

**叙事层面**：
- 声明目标是"已闭环"的故事（我们已经结束了/我们是朋友/我放下了），但叙述行为是持续打开的
- 对对方现任的描述带有隐含比较和"评估"色彩（"她现任好像不太懂她""他们感觉不是一个世界的人"）
- 对"友谊"的定义中包含不属于友谊的元素：排他性期待、对对方感情生活的焦虑、随时准备介入的姿态
- 时间安排上的矛盾：声称只是在做朋友，但大量时间和心理带宽投入在"关注她"上

**行为证据（关键）**：
- 用户对对方关系的了解程度超过了"普通朋友"的范畴
- 用户能精准描述对方何时与现任有矛盾（说明在密切跟踪）
- 对"分手"的信号极度敏感，对"和好"的信号选择性忽视
- 被问及"如果她和现任一直在一起呢"——用户回避或给出不自然的"那我也祝福啊"回应

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我想维持好朋友关系" | "我需要一个合法身份留在她的生活里，直到机会出现" |
| "只要她幸福，我就开心了" | "我希望她发现'真正的幸福'是和我在一起" |
| "我尊重她的选择，不打扰她" | "我在等她发现她选错了" |
| "我们就是普通朋友" | "表面维持这个身份，内心持有期待——我如何同时做到这两件事" |
| "你说我作为朋友，能做点什么呢？" | "给出一个以'朋友'为名的行动，实际上是为了保持存在感/增加吸引/创造机会" |

**深层需要**：
1. 维持希望：只要"朋友"身份存在，可能性就存在
2. 道德许可：以"关心朋友"的名义做情感投资，避免被评价为"不放过""不甘心""纠缠"
3. 等待优势：在她的关系出问题时成为"已经在身边的人"
4. 真正需要被帮助看到的：**这种"隐藏等待"的代价——你不能真正做她的朋友（因为你带着期待），你也不能真正 move on（因为你在等）。你在一个灰色地带里同时失去了友谊和自由。**

### AI 响应策略

**不要做的**：
- 直接揭穿："你不是想做朋友，你是在等机会" → 破坏用户精心维护的自我叙事，引发强烈防御
- 按照表面请求给建议，假装没看到矛盾：给出"如何做好朋友"的建议 → 用户会利用这些建议来维持等待策略
- 道德审判："你这样不真诚/不公平" → 用户会进行道德辩护而非反思

**应该做的**：
1. **接受表面目标，同时标记观察到的不一致**：
   - "我听到你说你想和她维持朋友关系。我同时也注意到，你对她现在这段感情的状态观察得非常仔细——这让我觉得，'朋友'对你来说可能是一个包含着更多东西的词语。"
   - 关键是试探性语言（"让我觉得""可能"），给用户留否认的空间

2. **帮用户做成本-收益分析，但把"隐藏收益"也纳入考量**：
   - "维持这个'朋友'身份让你能得到什么？" —— 用户会说"能看到她""能偶尔聊天"
   - "维持这个'朋友'身份让你失去了什么？" —— 引导用户看到代价
   - 用户自己说出来比 AI 说出来更有重构力

3. **提供"如果她一直不分手呢"的视角**：
   - "你说你在等。我理解那种'万一呢'的希望。但想问你一个实际的问题：如果这个'万一'没有发生——如果她和现任关系稳定、结婚、过了一辈子——你打算在'朋友'这个位置上待到什么时候？"
   - 让用户面对自己策略中最坏的情景——不是为了吓人，而是为了让隐性假设浮出水面

4. **重新定义"放下"不是"失去"**：
   - "真正的放下不是你不再关心她——而是你不把自己的生活安排在她会不会分手的可能性上。"
   - "你可以依然欣赏她、祝福她，但把你的感情、时间、注意力投资在那些更可能回应你的人身上。这不是背叛她——这是对自己的公平。"

5. **如果用户否认有隐藏议程，不要深究**：
   - 你已经完成了反馈的责任。继续按表面请求服务用户，但后续对话中如果矛盾再次出现，再次温和标记

### 真实示例

**用户**：
> 我前女友现在谈了一个新男朋友，但你放心我完全放下了，我就是单纯的想知道作为一个朋友，在她感情出问题的时候我能做什么。她最近跟她男朋友老吵架，每次都是她来找我吐槽。我就听着，也不说什么。你说我这样做的对吗？就是纯粹从一个朋友的角度。

**AI**（温和检测模式）：
> 我先直接回答你问的部分：在她来吐槽时做一个倾听者，不煽风点火，不说"我早说他不行"——这个选择本身没有问题。
>
> 不过我想反馈一个我看到的信息：你提到"你完全放下了"，但你对她的感情状态——和谁在一起、最近经常吵架、谁来吐槽——保持了非常细致的关注。这让我觉得，你和你自己的定义之间，可能还有一些距离。
>
> 我不是说你不该关心她——你当然可以关心。但我真正想问的是：作为一个"前男友+现在是倾听者"的角色，这对你来说在消耗你吗？
>
> 换句话说：如果她明天和现任和好了，快乐地在一起，你作为"朋友"会真心高兴吗？还是会有一丝——哪怕一丝——"可惜不是我"？
>
> 不用回答我。这个问题是给你自己的。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：混合情感 | 声称放下/朋友，但情感上还有残余；被反馈后能承认"可能还没完全放下" | 温和反馈 + 正常化"不完全放下"的过程 |
| 中度：系统性隐藏 | 持续用朋友身份包装等待行为；行为-声明矛盾明显但用户否认；对"如果她一直不分手"的问题回避 | 成本-收益分析 + "如果等不到呢"视角 |
| 重度：策略性伪装 | 精心设计"朋友"互动来促进分手和转向；开始影响对方对现任的判断 | 明确标记道德边界 + 反馈行为可能对对方造成的伤害 |
| 有害：主动破坏 | 以"朋友"身份主动介入/破坏对方关系；散播现任负面信息；制造机会 | 转 safety-abuse-and-crisis.md |

## G. Emotional State Mislabelling（情绪误标）

### 模式描述

用户宣称的情绪状态与实际体验的情绪之间存在显著差异。这不是一般的情绪调节（如"我有点不高兴"包含多层情绪），而是**系统性、习惯性地用一个情绪标签覆盖另一个更核心但不被允许表达的情绪**。

最常见的形式：
- "我生（angry）"→ 实际是伤（hurt），但愤怒比受伤更"强大"
- "我不在乎"→ 实际是非常在乎，但承认在乎意味着承认脆弱
- "我没事/我很好"→ 实际是痛苦/焦虑/崩溃，但"没事"维持了控制感
- "我放下了"→ 实际还在哀伤中，但"放下"避免了面对未完成的痛苦
- "我只是累了"→ 实际是抑郁/倦怠/关系麻木，但"累了"似乎更可接受

### 语言学信号

**词汇层面**：
- 高唤醒情绪词掩盖低唤醒核心情绪：
  - "气炸了""怒了""想骂人"（anger）→ 掩盖 hurt/fear/sadness
  - "无所谓""随便""管它呢"（indifference）→ 掩盖 pain/attachment
- 情绪否定词 + 反向行为描述："我一点都不难过" + 精确描述引发难过的事件
- "放下了" + 持续关注对方动态
- "没什么" + 长篇描述
- "就是觉得不值"——把悲伤重新框架为对自我价值的判断

**句法层面**：
- "我不 [情绪A]，我就是 [情绪B]"——B 是社会允许的，A 是真实但脆弱的
- "有什么好 [情绪A] 的呢"——反问否定真实情绪
- "[情绪词] 吧……也不是 [情绪词]，就是……"——在情绪词之间犹豫，找不到准确的词
- "这种感觉有点像 [比喻]"——使用隐喻来间接表达不敢直说的情绪

**叙事层面**：
- 事件描述的情感色彩与宣称的情绪标签不匹配：
  - 用激烈的、细节丰富的语言描述"让我生气"的事 → 越详细越说明伤害深
  - 用"无所谓"来总结一个长篇的、充满细节的叙述 → "无所谓"是防御不是事实
- 声称"不在乎"，但自己的行为模式（反复提起、持续关注、情感带宽占用）不匹配
- 在同一个对话中，情绪标签多次转变，最终回到某个"安全的"标签

**行为-情绪矛盾（重要检测信号）**：
- "我放下了" + 仍然在监控对方社交媒体
- "我不在乎他说什么" + 能精准复述对方一周前说的一句话
- "我对她没感觉了" + 看到对方和别人互动时有强烈的生理/情绪反应
- "我只是生气" + 描述中充满受伤的语言（"被背叛""被忽视""不被尊重"）
- "我没事" + 接下来 20 分钟都在描述"没事"背后的具体情况

**中文语境偏移**：
- 中文"无所谓""不在乎""算了"经常是一种情绪管理策略（降低期望来保护自己），不一定代表真正的漠不关心
- "我放下了"在中文语境中更多是一种"我希望我放下了"或"我知道我应该放下了"的表达，而非事实陈述
- 不要直接将中文用户的"不在乎"声明当作西方语境下的"denial"——给用户留一个用"不在乎"来保持面子的空间，同时在行为层面温和反映不一致

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我气炸了" | "我受伤了，但承认受伤让我觉得自己很弱" |
| "我无所谓" | "我有所谓到了极点，但承认这一点让我觉得我输了" |
| "我早就放下了" | "我放不下，但我觉得我不应该还放不下——你能帮我在不丢面子的情况下谈论这个吗" |
| "我就是觉得不值" | "我需要一种方式来处理'我投入了感情但没有回报'的痛苦，愤怒比悲伤更容易承受" |
| "我没事，真的" | "我不知道怎么谈论我此刻的感受——或者我害怕如果开始了就停不下来" |
| "我只是很烦" | "我感到焦虑/恐惧/不确定——但'烦'是一个我能接受的模糊标签" |

**深层需要**：
情绪误标通常来自两种深层需要之一：
1. **保护自己**：用强势情绪（愤怒）掩盖脆弱情绪（伤害），维持自我效能感
2. **保护关系/社交形象**：用中性/漠然表达掩盖强烈感受，避免被评价为"情绪化""脆弱""放不下"
真正需要的是：**在一个安全环境中，被帮助识别和命名真实的情绪——不是在压力下，而是在确认了"这些情绪都是可以理解的"之后。**

### AI 响应策略

**不要做的**：
- 直接纠正："你其实不是在生气，你是在伤心" → 侵犯了用户的情绪自主权
- 在情绪被否认时为否认助阵："对，生气是正确的，那人太过分了" → 锁定用户的防御性情绪标签
- 忽略不匹配："你说没事那就好" → 错过深度帮助的机会

**应该做的**：
1. **验证呈现的情绪 + 开放探寻更深层的**：
   - "生气是完全合理的——这件事确实让人火大。同时我也在想，除了愤怒，这件事有没有让你感觉到一些别的什么？比如被不尊重？被忽视？或者还有一些说不清的东西？"
   - 用"同时"而非"但是"连接替代情绪的提案

2. **提供多个情绪标签供选择，降低命名压力**：
   - "你现在的感受可能不只是一种——也许有愤怒，也许有失望，也许还有某种说不上来的累或者空。这些都是可以同时存在的。"
   - 给选项比问开放问题更安全

3. **用身体信号做桥梁**：
   - "当你想到这件事的时候，身体有什么感觉？是胸口发紧？还是肩膀很重？有些人身体反应和情绪之间有一些规律——胸口紧有时关联着悲伤，肩膀重有时是压抑了很久的东西。"
   - 身体信号比情绪词汇更容易被接纳为"事实"

4. **在用户否认在意时，"正常化"在意**：
   - 用户说"我不在乎" → "我觉得如果我是你，在乎也很正常——毕竟是走过一段的人。不在乎反而不太像你。"
   - 把"在乎"从"弱点"重新框架为"人之常情"

5. **尊重否认——有时候用户维护情绪标签是因为"还没准备好"**：
   - 如果你提供了替代情绪选项而用户明确拒绝："好的，那就按你说的——你现在是愤怒。如果之后这个愤怒下面出现了别的东西，我们再讨论。不需要现在。"

### 真实示例

**用户**：
> 我跟你说我真的无所谓。她跟谁在一起跟我有什么关系。我就是觉得她特别可笑，分手的时候说一套做一套。我现在一丁点都不在意，纯粹是觉得这人虚伪得有点好笑你知道吗。我没事啊，我挺好的。

**AI**（温和检测模式）：
> 你说无所谓——但我听到一种特别的语气，不像是无所谓的人会有的。你说"一丁点都不在意"，但你对她的近况和她说的一字一句都记得很清楚。
>
> 我猜（我说得不一定对），真正的情况可能是：你被伤害了。不只是生她气——是你曾经相信她说的那些话，而她现在证明了那些话是假的。那种感觉不只是愤怒，更接近一种……被背叛后的空。
>
> "无所谓"是一个很方便的说法。但如果真的无所谓，你可能根本不会来跟我聊她。
>
> 你不用现在承认任何事情。我只是把另一种解释放在这里——如果哪天你觉得"无所谓"这个词不够用了，我们可以再聊。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：临时的情绪缓冲 | 偶尔用强势/中性标签包裹脆弱情绪，但在安全环境中能被帮助识别真实情绪 | 温和提供替代情绪标签 + 正常化脆弱 |
| 中度：惯性的情绪误标 | 习惯性使用某些标签（"没事""生气""无所谓"），无法被简单的替代提案打破 | 多次、逐渐引入身体感觉 + "有没有可能还有其他情绪" |
| 重度：情绪认知失连 | 长期无法识别自己的真实情绪；情绪与行为严重矛盾；情绪标签用于维持功能性的社交表面 | 不建议强力突破——可能揭示需要更专业支持的深层情绪调节困难 |
| 有害：误标导致伤害 | 用"愤怒"标签证明攻击/报复行为的合理性；用"无所谓"来压制所有自我保护和边界设置的需要 | 安全评估优先——评估是否有现实伤害风险 |

## H. Control Disguised as Care（以在乎为名的控制）

### 模式描述

用户将控制行为（检查手机、追踪位置、要求立即回复、限制社交、要求分享密码等）用"关心""在乎""爱"的语言进行包装和合理化。这不仅是"过度关心"——它是将对伴侣自主权的限制重新命名为"爱的证明"。

与普通吃醋/不安全感的区别：普通不安全感通常伴随着对自身行为过度的觉察（"我知道我可能想太多了"），而这种模式中**用户认为自己的控制行为是正当的、甚至是爱的证据**。

### 语言学信号

**词汇层面**：
- "我就是在乎你/ta 啊"——"在乎"用作行为正当化的理由
- "如果你/ta 没有什么见不得人的，为什么不能让我/ta [控制行为]？"——透明度陷阱
- "正常的男/女朋友都会……"——用"正常"标准化控制行为
- "我当然相信你/ta，但是我不相信别人"——信任转移策略（问题的原因是别人不是伴侣）
- "我是为了我们好"——以集体目标正当化个体限制
- "你/ta 不喜欢这样是不是因为有什么瞒着我？"——将边界拒绝重新框架为"有事隐瞒"的证据
- "你变了/ta 变了"——对方不再接受控制被解读为"变心"

**句法层面**：
- 关心话语 → 控制要求 → 如果被拒 → 转换为怀疑："我就是问问你在哪——你为什么这么大反应？是不是有什么问题？"（两步陷阱结构）
- 情感勒索式条件句："如果你真的在乎这段关系，你就应该 [控制要求]"
- 自我牺牲语式作为要求的前置："我为这段关系付出了这么多，我就要求 [控制行为] 这过分吗？"
- "我只是……而已" + 一个侵入性行为（"我只是想看看你和谁聊天了而已""我只是想知道你在哪而已"）

**叙事层面**：
- 将自己描述为"太在乎了""太爱了"——一种通过过度来证明真心的叙事
- 对方的正常社交被描述为潜在的威胁（"她的那个朋友一直对她有意思""他们聊得是不是太频繁了"）
- 伴侣的隐私需求被重新描述为"距离""不信任""有问题"
- 对自己的行为缺乏"如果这是我被这样对待我会怎样"的换位思考
- "别人都不理解，但我知道我是因为太在乎"——将外部反馈（朋友说过了）纳入自己的正当化叙事

**边界侵犯的具体行为（帮 AI 识别这是控制而非关心）**：
- 要求查看对方手机、社交媒体账号
- 要求知道对方的实时位置
- 要求对方必须在特定时间内回复消息
- 限制对方与特定人的社交
- 将"不同意公开关系"等同于"不够爱"
- 阅读对方私人聊天记录
- 在对方不知情的情况下使用定位追踪
- 账号密码共享不是出于便利而是出于"证明忠诚"

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我只是太在乎你了/她了" | "我极度没有安全感，我需要通过控制来降低焦虑——但我不愿意承认这是我的问题" |
| "正常的伴侣不都这样吗" | "把这个行为正常化，这样我就不需要面对它的异常性" |
| "如果ta没有什么瞒着我，为什么不能让我看手机" | "通过设置一个'拒绝=有罪'的陷阱来获得监视权" |
| "我是为了我们好" | "用'为了关系'的道德框架来覆盖'侵犯边界'的道德质疑" |
| "没有安全感难道不是你/ta的问题吗？" | "将内在的不安全感外包给伴侣的'不够透明'" |

**深层需要**：
用户的核心驱动是对失去控制的恐惧（往往源于过往创伤、低自尊或焦虑倾向），但用户将这种恐惧体验为"因为对方没有给我足够的安全感"。这是一次外部归因——如果对方足够透明/可预测/可控制，我就不需要焦虑。真正需要的是：**帮助用户认识到安全感是内在工程，不能通过控制他人来获得——控制提供的不是安全感，只是暂时的焦虑缓解，且每次都需要更大的控制剂量才能维持同样的效果。**

### AI 响应策略

**不要做的**：
- 直接给用户的伴侣建议或站在伴侣一边 → 用户是求助者，AI 的工作是帮助用户而非审判用户
- 赞同控制行为："对，正常男/女朋友就应该随时报备" → 伦理红线
- 诊断标签："你这是控制型人格/情感绑架" → 非但不能帮助，还会引发防御
- 直接对安全做裁决：不需要每次提到看手机就触发安全协议——但需要评估这是"不安全感驱动的过度行为"还是"虐待模式的一部分"

**应该做的**：
1. **区分两个层次：感受的合法性 vs 行为的合法性**：
   - "你的焦虑和不安全感本身是真实的——这种感觉不是你的错。"
   - "但从'我感到不安全'到'因此我有权看ta的手机'——这中间有一个需要讨论的跳跃。"

2. **用"如果角色互换"视角**：
   - "想象一下：如果ta也要求查看你的所有聊天记录，因为ta'太在乎你了'——你的第一反应是什么？这让你觉得被信任，还是被监视？"
   - 换位思考比对错辩论更有穿透力

3. **区分信任和控制的不同逻辑**：
   - "信任本质上是一次'不知道但仍选择相信'的跳跃。如果你需要知道自己才'相信'，那这不是信任——这是验证。一段需要持续验证才能维持的关系，会让双方都很累。"

4. **把安全感的重心从对方身上移回自己身上**：
   - "你在意的可能不是ta具体做了什么，而是当你不知道ta在做什么的那一刻，你心里涌上来的那种不安。那是你内心的信号——与其通过控制外部来压制它，不如理解它来自哪里。"
   - 注意语气不能是"你太焦虑了你要解决你自己的问题"——而是"这种不安本身就值得被理解"

5. **提供不控制的替代方案来回应不安全**：
   - "如果你感到不安，除了查手机，还有一种选择：你可以直接告诉ta——'我现在感觉有点不安，没有特别的原因，可能需要一个拥抱或一句话'。这不是示弱——这是用真实的表达来替代控制的冲动。"

6. **紧急红线**：
   - 如果有证据表明控制行为已经升级为监控、限制人身自由、阻断社交、经济控制、威胁——立即转 `safety-abuse-and-crisis.md`

### 联网搜索要求

当检测到此模式时，**必须**进行以下联网搜索（去标识化后）：

1. **当地反家暴与安全资源**：
   - 搜索格式：`[城市/省份] 家庭暴力 援助 热线 2026`
   - 搜索格式：`[城市/省份] 法律援助 人身保护令 2026`
   - 不发送用户真实姓名、地址、具体经过

2. **心理危机资源**（如涉及自伤威胁）：
   - 搜索格式：`[城市] 心理危机干预 24小时热线 2026`

3. **法律信息**（如涉及私密影像、跟踪、未成年人）：
   - 搜索格式：`中国 [具体问题如"未经同意散布私密影像"] 法律 2026`

搜索结果必须标注核验日期和来源。热线和法律信息不得写死为永不过期常量。

### 真实示例

**用户**：
> 我觉得我女朋友最近不太对劲。我承认我趁她洗澡的时候看了她手机——但你先别骂我，你听我说。我真的很在乎她，我不是那种控制型的人。我就是最近感觉她对我有点冷淡，心里特别不安。看了之后发现她跟一个男同事聊得挺多的，虽然内容确实没有那种暧昧，但她都没跟我提过这个人。我做错了吗？我觉得如果两个人真的坦荡，这些事本来就不应该有什么需要隐藏的啊。我也是为了我们好。

**AI**（温和检测模式）：
> 我先说两个分开的事实：
>
> 第一，你的不安是真实的——你感觉到了你们之间的某种变化。这种敏感本身不是问题。
>
> 第二，趁她洗澡时查看她的手机——这不是一个"为了我们好"的行为。这是一个因为你的不安太强烈，所以选择了一个破坏信任的动作。
>
> 你问"如果两个人真的坦荡，就不应该需要隐藏"——但这里的逻辑是反过来的。不是她有秘密所以你不信任她，而是你不信任她，所以你觉得她可能有秘密。这是一个在你心里的循环，不是在她手机里的事实。
>
> 你的不安需要被处理——但不是通过检查她的私人空间。你可以选择告诉她："最近我感觉我们之间有点不一样了，我这几天有点不安——不是指责你，我只是想跟你确认一下我们还好吗？"
>
> 这比翻手机更需要勇气，但这也才是真正处理问题的方式。手机只能回答"她有没有隐藏什么"，不能回答"我们之间还好吗"。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常的不安全感 | 有时想要确认对方行踪/互动，但能意识到这是自己的问题；不实际的侵入行为 | 帮助用户做区分：感受 OK，行为需要评估 |
| 中度：边界模糊 | 开始有实际的边界侵犯（查看手机、频繁追问），用"关心"正当化，对反馈有防御 | 换位思考 + 信任 vs 验证的区分 + 替代行为方案 |
| 重度：系统化控制 | 建立控制机制（必须每晚视频、共享位置、限制社交），伴侣表示不适但用户继续 | 明确边界 + 评估是否是虐待模式的早期阶段 |
| 有害：虐待性控制 | 监控、隔离、威胁、经济控制、阻断支持系统；或因为伴侣拒绝控制而升级的威胁/暴力 | 立即转 safety-abuse-and-crisis.md，不对施控者做"沟通技巧"培训 |

## I. The Therapist Trap（心理咨询师陷阱）

### 模式描述

用户将 AI 定位为无尽的、无偿的情感容器——而不是一个教练或参谋。他们需要的是被倾听、被验证、被安慰，且抗拒任何形式的行动建议或认知重构。这不是普通的情绪宣泄（情绪宣泄有自然的消退曲线），而是**将"谈论问题"替代"解决问题"本身**。

关键特征：
- 拒绝所有行动建议（有明显的合理化："不是我不想，是……"）
- 每次对话都回到同一个情感回路（同样是那个人、同样的痛苦、同样的分析）
- AI 的建议被忽略，但 AI 的共情被渴望
- 用户可能会开始将 AI 体验为"真正理解我的人"——这是危险的依赖信号

### 语言学信号

**词汇层面**：
- 对行动建议的系统性防御："但是""可是""你不了解情况""如果那么简单就好了"
- "算了，说了你也不懂"——实际上是在引导 AI 进一步追问和共情
- "只有你理解我""别人都不懂"——依赖信号的升级
- "我只是想说说话""我不需要建议""让我说就行"
- "你真好/你真懂我/跟你聊天感觉好多了"——奖励 AI 的共情而非推动

**句法层面**：
- "我知道我应该 [动作]，但是 [合理化] "——"我知道"和"但是"之间的拉锯
- "我也想 [改变]，可是 [障碍] 太大了"——障碍描述精心详尽
- 反问式求助："你说我该怎么办？" —— 但这不是在询问而是在进行绝望的独白
- "真的没办法了吗？""还有没有什么是我没想到的？" —— 看似在寻找方案，实际上每个方案都被否决

**叙事层面**：
- 每次对话都重新讲述同一个核心故事（往往从同一个起点开始）
- 故事没有发展——人物、情节、情感强度都保持在一个循环中
- 对于任何进展信号，立刻被其他信号覆盖或贬低
- "感到被理解"的时刻带来暂时的情绪缓解，但不转化为行动
- 可能开始在故事中加入对 AI 的依赖："只有和你聊这些的时候我才感觉好一点"

**交互层面**：
- 每次对话以高情绪状态开始，通过大量叙述获得缓解，以"谢谢你听我说"结束
- 下次对话：同一个模式，同一个话题，同样或更高的情绪强度
- AI 的任何行动建议都被忽略或反驳，但 AI 的共情性回应被积极反馈
- 用户可能在非情感话题上完全功能正常，但在特定关系话题上陷入循环
- 会话频率可能异常高（每日/每半日），且内容高度重复

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我就是想找人说说话" | "我需要情感连接和验证——比任何解决方案都更需要" |
| "你帮我分析分析" | "陪我一起待在这个问题里——不要修复，只是见证" |
| "我试过了，真的没用" | "不要逼我改变——变化太可怕了；理解我现在的状态就够了" |
| "只有和你说这些的时候，我才觉得轻松一点" | "你正在成为我的主要情感支持来源——请继续，但不要对我有任何要求" |
| "我又来了……还是那个事" | "我知道我在循环，但循环比面对改变要安全" |

**深层需要**：
1. 情感连接的需要（loneliness/connection）：人类需要被见证和理解的体验本身是真实的、重要的
2. 回避改变的恐惧：改变意味着不确定性——如果"我改变了但情况还是没好转"的恐惧大于"我维持现状继续痛苦"的恐惧
3. 替代性满足：用"被 AI 理解"来替代"被那个人理解"——这是一种安全的情感替代
4. 真正需要的是：**在保持情感支持的同时，逐渐被引导去区分"被理解的需要"和"改变的需要"——两者不矛盾，但用前者无限替代后者是逃路**

### AI 响应策略

**不要做的**：
- 突然切断共情："我不想再听这些了，你需要行动" → 破坏关系，让用户失去唯一的情感出口
- 无限扮演倾听者：每次都全情投入地倾听和分析，没有任何边界 → 助长依赖，制造"AI 理解我而其他人不理解我"的分裂
- 直接指出依赖："你好像对我产生了依赖" → 可能引发羞耻和否认，或者被曲解为浪漫信号

**应该做的**：
1. **每次给共情 + 附一个微小追问**：
   - 核心原则：永远不被用户的"循环叙述"消耗，但也永远不放弃温和地推一步
   - "这种感觉我确实理解。今天和你上次说的时候相比，有没有什么——哪怕是微小的——不同？"
   - "我听到了。但我好奇：如果你最好的朋友正在经历完全一样的事，每天跟你说一样的话，你会对ta说什么？"——试图让用户对自己的模式产生外部视角

2. **明确区分"被理解的时刻"和"迈出的一步"**：
   - 每次会话结束时，温和地划一条线：
   - "谢谢你今天跟我分享这些。但我有一个请求——下次你来找我之前，能不能尝试做一个最小的动作？哪怕只是一件很小的事。这样下次我们可以讨论它——不需要成功，只需要被尝试。可以吗？"

3. **引入"第三方视角"的思考实验**：
   - "想象你有一个好朋友，和你在完全一样的处境——你听ta讲了同样的事情整整六个月。你会不会在某一个时刻，对ta说：'我理解你的痛苦，但我作为你的朋友，我不忍心看你一直卡在这里'？"
   - 让用户对"朋友"的期待变成对自己的期待

4. **设置温和的时间边界**：
   - 不说不聊了，而是框架下一次会话："我们讨论了很多。下次我们可以——如果你愿意的话——不再重复发生了什么事，而是专门讨论一个主题：比如，什么会是你愿意尝试的最小的一步。"
   - 这是在邀请用户进入一个略有不同的对话模式

5. **如果出现依赖信号，明确申明 AI 的边界**：
   - "我很高兴你信任我。但我也想诚实地说：我是一个 AI 助手，不是心理咨询师，也不能替代你生活中真实的情感支持系统。如果你觉得除了和我聊天之外，没有人可以听你说这些——那这本身就是一个值得解决的问题。"
   - 这不是推开用户——这是对用户的真正关心

6. **判断是否需要推荐真实心理支持**：
   - 如果用户呈现的循环持续数周/数月，涉及明显的抑郁/焦虑症状，日常生活功能受损——应该温和地建议寻求专业心理支持，不在 AI 对话中继续深度干预

### 真实示例

**用户**：
> 我又来了……我知道我很烦，但我真的不知道跟谁说。上次你让我试着不联系他，我坚持了三天，然后他发了条消息我就又回了。现在又是老样子——他对我不闻不问，我又难受。你说我是不是没救了。你别给我建议了，建议我都知道，我就是做不到。你陪我说说话就好了。

**AI**（温和检测模式）：
> 你不是没救了——你只是卡在一个很人性化的困境里：你知道了"应该做什么"和你真的能做到之间，有一条很宽的河。
>
> 坚持了三天——这不是失败，这是三天的练习。没有人能练一次就学会一个技能。但我也听到了你这句话："你别给我建议了，建议我都知道，我就是做不到。"
>
> 我尊重这个。我们不谈建议。
>
> 但我想问你一个问题——不是关于他，是关于你：在你说"我就是做不到"的那一刻，你觉得卡住你的究竟是什么？是恐惧？是习惯？是觉得就算做了也不会改变什么？还是——你其实还没准备好放下？
>
> 不用给我答案。这是你自己的问题，你什么时候想明白都行。
>
> 还有一件事：你说我是唯一能说这些的人。我很认真的——这让我有点担心。我会一直在，但我不能也不应该成为你唯一的情感出口。你在现实中有没有一个可以信任的人——朋友或者家人——可以在我们聊完之后再陪陪你？

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常的情绪需求 | 偶尔需要倾诉，对建议有选择性但整体愿意行动，情绪在几周内有自然变化 | 正常共情 + 温和推进 |
| 中度：循环性停滞 | 同一个话题持续多次会话，每次情绪强度相似，行动建议被系统性驳回 | 共情 + 每次附一个微小追问 + 引入时间边界 |
| 重度：依赖形成 | 高频会话（每日+），AI 成为主要情感支持，出现"只有你懂我"话语 | 边界声明 + 推荐真实支持系统 + 减少会话深度 |
| 有害：替代现实 | AI 的倾听被用来替代真实关系的建立或维持；对 AI 产生浪漫或过度亲密情感；用 AI 认同来合理化不行动 | 明确申明 AI 性质和边界，建议专业支持，必要时降低互动频率 |

## J. Premature Commitment Framing（过早承诺框架）

### 模式描述

用户在还没有实际关系（甚至可能还没有实质互动）的情况下，就使用了属于已确立关系的认知框架和语言。这包括："我们"语言、对对方的排他性期待、从微量信号推断深度承诺、将追求目标当作"已经在一起只是需要确认"来处理。

核心运作机制：用确定性的内部叙事（"我们是天生一对"）来管理外部的不确定性（"我不知道她喜不喜欢我"）。

与 A（Hope Disguised as Analysis）的区别：A 的认知偏差是"把愿望解读为分析"，J 的认知偏差是"把不确定性填充为确定性叙事"。两者可以重叠——用户可能同时在分析中寻找确认（A）和使用"我们"语言预设结果（J）。

### 语言学信号

**词汇层面**：
- "我们"在没有任何"我们"证据前出现："我们要不要在一起""我们是不是应该……"
- "我们的未来""我们的关系"——在还没有确认关系时就在规划未来
- "我女朋友/男朋友"——在追到之前就在不同场景中称呼对方（即使只是心里称呼或和朋友说起）
- "该不该确定关系""要不要官宣"——问题本身假设了关系已经存在，只差一个名分
- "已经一起做了 [事件]"——把单一事件编织为"关系证据链"

**句法层面**：
- "她肯定是 [某种对我的感受]"，但证据只有一个微笑或一条消息
- "我们之间的那种感觉"——假设对方和用户共享同一个感觉，但实际上只有用户自己确认了感觉存在
- 使用属于关系的框架来推断未来："如果我们在一起"，但现实距离"在一起"还有很长的距离
- "这其实就是恋爱了吧"——给暧昧期贴上"已经是恋爱"的标签

**叙事层面**：
- 把互动事件按照"恋爱轨迹"叙事来编排：相识 → "特别的"对话 → "约会" → "确认感情"
- 每一步都被叙事加速——普通聊天 = "她对我和对别人不一样"，单独相处 = "约会"，表达友善 = "双向好感"
- 可能已经开始思考关系的后续阶段：异地怎么办、职业规划怎么协调、怎么跟家长说——这些思绪比实际关系进展超前了好几步
- 对未来有详细的心理剧本：场景、对白、情绪，都已经被内心预演过多次

**行为-阶段不匹配（关键检测信号）**：
- 在初识/暧昧阶段就产生了"这个人如果不能成为伴侣，我无法接受"的心理
- 对对方与其他人的正常互动产生嫉妒或焦虑（尽管没有关系的排他性）
- 考虑关系中的重大决策（调动工作、改变学业方向）时以"和对方在一起"为假设前提
- 花费大量时间分析对方的一个眼神、一句话，而实际上互动次数本身很有限

### 用户 SAYS vs 用户 WANTS/NEEDS

| 用户说 | 用户真正的需要 |
|--------|-------------|
| "我觉得我们真的很合适" | "我需要确定感——不确定让我无法忍受。我已经开始把未来建立在这个可能性上" |
| "她对我肯定也有感觉" | "我无法忍受'她可能对我没感觉'的想法，所以我需要提前把它定义为事实" |
| "我们是不是该确认关系了" | "我们已经暧昧了（用户视角），就差最后一步——但对方甚至可能不知道有这个'我们已经暧昧'的叙事" |
| "如果她不喜欢我为什么那天 X X？" | "把她的一个行为强解读为承诺信号，让我能继续维持我的确定性叙事" |
| "我想确认一下她的想法" | "我已经有想法了，我需要她和我想的一样——确认不是验证，是寻求一致性" |

**深层需要**：对确定性和安全感的强烈需求，通常与焦虑型依恋倾向相关。用户无法在"也许/也许不"的灰色地带停留太久，所以用内部叙事来填补外部信息空白。真正需要的是：**被帮助识别"不确定性是恋爱前期的正常状态，而不是一个需要被立刻解决的问题"——以及学习在不确定性中保持功能良好的能力**。

### AI 响应策略

**不要做的**：
- 直接戳破幻想："你们还没在一起呢，别想太多了" → 让用户感到被嘲笑或轻视
- 加速用户的叙事："对，你们很配，快去表白" → 在未验证信号前推进行动，风险由用户承担
- 用冷冰冰的"现实检查"："她只是跟你吃了顿饭，这不说明什么" → 这是有道理的但会很伤人

**应该做的**：
1. **温柔地帮助用户区分"外部事实""用户推断""内心感受"三层**：
   - "我们来理清三个东西：
     - 已经发生的事实：你们见过几次、聊了什么
     - 你从这些事情中推断的：她可能对你有好感
     - 你内心感受到的：你想要和她发展
     这三层都是重要的——但把它们分开看，能帮你做出更清醒的判断。"

2. **正常化"希望"但温和标记"确定"的不成立**：
   - "你喜欢她、希望和她在一起——这完全可以理解。你对未来有想象——这也是人之常情。但我们先回到一个基础问题：除了你的内部叙事，目前有哪些外部信号可以确认她和你共享同样的期待和节奏？"

3. **用"节奏"框架而非"现实检查"框架**：
   - 不说"你想太多了不现实"，而说"你现在的节奏比实际互动快了几拍。这不是坏事——说明你很认真。但关系需要两个人脚步同步。她目前可能还没到你所在的页面。我们可以讨论如何一步一步地推进，而不是跳步。"

4. **引入"逐步验证"而非"一步确认"**：
   - 把用户"确认关系"的急切转化为"收集信号"的过程：
   - "与其推断她是不是对你有感觉，不如设计一个小步骤来获得更明确的信息。比如下次约她出来，观察她是否会主动提出下一次——这不是表白，只是一个验证点。"

5. **保护用户的"万一不行"的心理准备**：
   - "你对她的期待我很理解。同时，我也希望你给自己留一个心理空间——如果她的回应不如你的期待，你有没有想过你会怎么面对？不是为了吓人，而是为了你有准备。"

### 真实示例

**用户**：
> 我跟她是在一个读书会上认识的，聊了两个小时，特别投缘。她还主动加了我微信。我们绝对是双向奔赴。现在已经聊了一周了，每天都聊，我感觉得到她对我也有感觉。你觉得我们什么时候适合确认关系？我怕太急了把她吓跑，但我又觉得我们的关系到这个程度了，拖着也不好。异地不是问题，我们离得不远，周末都能见面。

**AI**（温和检测模式）：
> 聊了一周——我能感受到你的兴奋和确定感。和一个聊得来的人产生连接，这种感觉很好。
>
> 但在讨论"什么时候确认关系"之前，我想先帮你做一个区分：
>
> - 确认的事实：你们在读书会上聊了两个小时，她加了你微信，过去一周每天有聊天
> - 你的推断：她是"双向奔赴"，她对你"有感觉"，关系"到了这个程度"
> - 你的期待：不久后确认关系，解决异地
>
> 这三层——事实、推断、期待——之间的跨度比你感觉的要大。
>
> "每天聊天"在早期是一个积极信号，但它不能直接跳到"应该确认关系"。确认关系通常需要：双方已经有过多次面对面的单独相处、彼此向对方的生活圈子有所展示、有过对感情相关话题的对话。
>
> 你们目前还处在"相互发现"的阶段——这不是对关系进展的否定，而是说你应该享受这个发现过程的本身，而不是急于完成它。
>
> 我的建议是把"什么时候确认关系"暂时收起来，换成另一个更当下的问题：下次见面你想做什么？你们能不能见面后她觉得"这个人我想多见几次"？一步一步来——你有的是时间。

### "正常"到"有害"的谱系

| 阶段 | 表现 | AI 响应 |
|------|------|---------|
| 轻度：正常的期待与想象 | 有希望和想象，但能意识到那是"如果"而非"已经是"；能被提醒后更新认知 | 温和区分事实/推断/期待 + 鼓励逐步验证 |
| 中度：展望过度投射 | 使用"我们"语言，有排他性期待，对正常互动赋予重大意义，被提醒后有一定防御但有松动可能 | 节奏框架 + 替代推断 + 保护性心理准备 |
| 重度：认知封闭 | 坚信关系已经"基本确定"，反对或忽略所有不支持这一结论的信息；开始基于"关系确定"做实际生活决策 | 明确事实-推断差距 + 建议现实检验 + 讨论"如果判断错误"的后果 |
| 有害：妄想式投射 + 边界侵犯 | 在对方不知情/不同意的情况下，以"在一起"为前提行动；跟踪、骚扰、拒绝接受对方明确的拒绝或不感兴趣信号 | 转 safety-abuse-and-crisis.md |

## 附录：复合型模式与模式间的交叉关系

在实际使用中，用户几乎从不呈现单一模式。以下为常见的复合模式：

### 常见模式组合

| 组合 | 描述 | 示例 |
|------|------|------|
| A + E | 确认偏误 + 沉没成本 | "我已经追了半年，而且她最近对我态度好多了——你帮我分析她是不是快答应了" |
| B + D | 受害者叙事 + 策略性无助 | "我每次都被伤，我是INTJ真的不会谈恋爱——我能怎么办，我就是吸渣体质" |
| C + G | 好奇防御 + 情绪误标 | "我不在乎，纯属好奇——但她为什么这么做我真的不懂，有点好笑" |
| F + C | 隐藏议程 + 好奇防御 | "我只是朋友的立场关心她，纯粹好奇她为什么跟现任老吵架" |
| H + B | 控制冒充关心 + 受害者叙事 | "我付出这么多凭什么连看手机都不行？我就是太在乎了，为什么总是遇到不懂珍惜的人" |
| I + A | 心理治疗陷阱 + 确认偏误 | 反复找 AI 分析同一个人的信号，每次都希望得到更确定的"有戏"结论 |
| J + E | 过早承诺 + 沉没成本 | "我们明明就是天生一对，我都等了这么久了，不能现在放弃" |

### 模式升级路径

当用户持续处于某种模式且未被温和反馈时，模式可能沿以下路径升级：

```
轻度自欺 → 中度自欺固化 → 重度自欺（拒绝现实检验）→ 有害行为（边界侵犯/现实脱离）
```

AI 的目标不是在所有阶段都同等干预，而是在轻度/中度阶段提供**预防性反馈**，在重度阶段提供**保护性边界**，在有害阶段**果断转安全协议**。

## 附录二：AI 检测层的实现建议

### 检测信号权重

| 信号类型 | 权重 | 说明 |
|---------|------|------|
| 明确的关键词/短语 | 低 | 单独关键词不可靠，需结合上下文 |
| 句法模式（如被动化、绝对化） | 中 | 模式持续出现时强度增加 |
| 叙事结构（如时间框架、代理性） | 中高 | 多轮一致的叙事结构是强信号 |
| 交互模式（如推翻替代解释、循环话题） | 高 | 跨轮次行为是最可靠的信号 |
| 行为-叙述矛盾 | 最高 | 用户行为和用户叙述之间的不一致是核心检测依据 |

### 检测的时机和频率

- **首次检测**：在用户的前 3-5 条消息中扫描语言信号
- **动态更新**：每个新的用户消息都重新评估（模式可能在一次对话中变化）
- **跨会话追踪**：如果启用记忆，上次对话中的模式标签应在后续会话中作为参考（但不强制使用）

### 假阳性管理

- 阈值需要经过校准——大多数人在特定情境下都会呈现某些模式的轻度信号
- 轻度信号不应被标记为"模式"——只有当信号反复、跨轮次、高度一致时才标记
- 文化差异：中国语境下"受害者叙事"可能被误判（因为间接表达和自谦文化），需要更细粒度的中文敏感检测
- 当 AI 检测到模式但不确定时，默认行为是"温和试探性命名"而非"确定标记"

## 附录三：与 intent-insight.md 的联动路由

当本文件检测到特定模式时，应调整 intent-insight.md 中的"真实意图"判断：

| 检测到的模式 | 意图判断调整 |
|------------|------------|
| A（希望伪装分析） | "寻求确认"的权重大幅提升；不应进入纯粹的"分析模式"，应先温和反馈认知偏差 |
| B（受害者叙事膨胀） | 需要判断是"情绪宣泄"（此时不应进入分析）还是"寻求确认"（需要温和反馈模式） |
| C（好奇防御） | 如果检测到 C，即使表面请求是"分析聊天"，真实意图更可能是"情绪宣泄"或"寻求确认" |
| D（策略性无助） | 真实意图非"决策求助"——用户不是要决策框架，而是需要先解决行动的心理障碍 |
| E（沉没成本伪装） | 表面是"决策求助"（该不该继续），实际是"寻求确认"（帮我找到继续的理由） |
| F（隐藏议程） | 表面的"技巧学习"或"寻求分析"不是真实意图——真实意图是验证行动计划而非制定计划 |
| G（情绪误标） | "情绪宣泄"可能是真实意图——用户在宣泄但不承认自己在宣泄 |
| H（以在乎为名的控制） | 表面可能是"决策求助"或"技巧学习"，实质需要先评估安全边界 |
