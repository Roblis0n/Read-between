# Memory Protocol — 会话记忆与用户自主存档

read-between 默认不保存任何内容。此文件说明 skill 实际能做到和不能做到的，以及你可以如何自己管理重要的关系记录。

## 核心原则

1. **默认不记忆**：每次对话从零开始，分析后不自动保存任何内容
2. **会话内上下文**：在同一段对话中，read-between 可以引用之前的聊天分析和建议（由 AI 模型平台管理的对话上下文，skill 不控制会话生命周期和清除时间）
3. **不主动推销记忆**：只有你明确提出"保存""记住""帮我记录"时，才进入记录流程。read-between 不主动判断"这个里程碑应该保存"
4. **你拥有自己的数据**：所有记录保存在你指定的本地目录，格式为明文 Markdown
5. **skill 不提供自动化档案系统**：没有加密存储、没有原子写入保证、没有自动索引

---

## 会话内记忆（始终可用）

在同一段对话中，read-between 可以利用对话上下文来：
- 引用之前分析过的同一段聊天
- 记住你在本次对话中提供的星座/八字/MBTI 信息
- 保持对当前关系阶段和讨论话题的连续理解

**限制**：
- 会话上下文由 AI 平台管理，到达上下文窗口限制时较早内容可能被压缩或丢失
- 新对话 = 从头开始，除非你手动提供之前的记录
- read-between 不能跨会话保持记忆（这是 skill 指令文件的固有限制，不是功能缺陷）

---

## 用户自主存档

如果你想让某些分析或决定在对话结束后仍然可查，你有三个选项：

### 选项A：对话中直接保存

在对话中说"帮我把这段分析保存下来"或"帮我记录这个决定"。read-between 会：
1. 展示拟保存的完整内容和路径
2. 等待你确认
3. 写入你指定的本地目录
4. 重新读取验证写入成功
5. 报告结果

### 选项B：手动复制

对话中的重要分析、草稿或建议，你可以直接复制粘贴到你自己的笔记应用中。这是最安全、最灵活的方式。

### 选项C：使用下面的模板自行记录

每次重要互动或决定后，你可以使用推荐模板在自己的笔记中创建记录。模板是建议性的——你可以调整或忽略任何部分。

---

## 推荐记录模板

### 人物记录模板

```markdown
---
type: person
created_at: YYYY-MM-DD
---

## 基本信息
- 称呼：（你用的昵称或代号）
- 认识时间：
- 认识途径：

## 我已确认的事实
- （只写可以确认的行为——"她在2026年1月主动约我看了电影"）

## 我的感受
- （你对这个人/这段关系的感受）

## 我的理解（待验证）
- （你对她的行为的解释——"她可能对我有好感，因为..."。标注这是你的推测）

## 未知
- （你还不确定的事情）
```

### 关系决定记录模板

```markdown
---
type: decision
created_at: YYYY-MM-DD
---

## 我做了什么决定
- 追 / 不追 / 等等 / 放弃 / 表白 / 分手 / 复合

## 基于什么理由
- （具体信号、自我澄清、代价评估）

## 我的假设
- （我认为会发生什么）

## 退出条件
- （什么情况下我会重新评估这个决定）

## 复盘日期
- （建议设定一个未来的复盘时间点）
```

### 聊天摘要模板（建议而非原文保存）

```markdown
---
type: conversation
created_at: YYYY-MM-DD
---

## 时间范围
- 从 YYYY-MM-DD 到 YYYY-MM-DD

## 可观察行为
- 谁主动发起对话：
- 话题延展情况：
- 是否有约定的提出/履行：

## 我的解读
- （你对这次聊天的理解）

## 替代解释
- （至少一个不符合你预期的合理解释）

## 不确定
- （仅凭这次聊天无法判断什么）
```

## 记录质量建议

无论用哪种方式保存，建议遵循以下原则（来自 read-between 的分析方法论）：

1. **区分确认事实和你的推测**：你观察到"她这周主动发了3条消息"≠"她喜欢我"。前者是事实，后者是推测。建议在记录中分开写
2. **记录未知**：写下"我还不知道她XXX"比假装一切已知更有用
3. **保留原始时间戳**：回头看时，你会需要知道这个记录是什么时候写的——当时的判断可能因为后来的信息而过时
4. **复盘不覆盖原记录**：新认知应该追加为新条目，而不是修改旧条目。你需要看到自己判断的演变
5. **对方隐私**：记录时使用代号或昵称而非真实姓名

## 数据目录

如果你使用"选项A：对话中直接保存"，文件将被写入 `data-root.txt` 指定的目录。该路径是一个建议值——你可以修改它。

默认建议结构（由用户自行管理，skill 不自动创建）：

```
[你的数据目录]/
├── profile.md          # 你的长期偏好与底线（如有）
├── people/             # 人物记录（按你的需要创建）
├── relationships/      # 关系记录（按你的需要创建）
├── exports/            # 你手动导出的内容
```

---

## 旧推断的处理

当你回头查看旧记录时：
- 将长期未更新的推断视为**可能已过时**
- 新事实与旧记录冲突时 → 保留旧记录，追加新记录并标注"取代了XX日的判断"
- 实际行为始终比旧推断更权威

## 脚本验证

以下脚本用于检查已保存记录的结构和一致性。它们是辅助工具，不是自动化的记忆系统：

```powershell
# 检查数据目录结构和记录格式
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate_memory_store.ps1

# 校验单条记录的字段完整性
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate_record.ps1 -RecordFile <path>

# 检查不同关系目录之间的信息隔离
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/detect_cross_relationship_leakage.ps1
```

## read-between 明确不提供的

- ❌ 不提供加密存储（文件为本地明文 Markdown）
- ❌ 不承诺跨会话自动记忆（skill 文件架构的固有限制）
- ❌ 不自动检测"值得保存的里程碑"并主动建议保存
- ❌ 不假设或猜测用户想要保存什么——只有你明确提出时才保存
- ❌ 不在你要求删除/"忘记"某件事时连带删除你未明确指定的其他记录
