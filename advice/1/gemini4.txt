# 恋爱与亲密关系教练 Skill 深度审阅报告

## 1. 现有 Plan 评价与整体诊断

现有的 Plan 逻辑非常清晰，已经精准抓住了市场痛点和开源缺口：

* **立意极佳**：明确摒弃了“人格克隆（数字前任）”和“PUA 操控策略”，转向心理学、社会学支撑的关系健康度治理。
* **痛点抓得准**：准确识别了现有同类项目在“输入管线（解密容易崩）”、“输出可读性（用户不要看原始 JSON）”、“证据治理（乱贴 MBTI/依恋标签）”上的致命缺陷。
* **差异化明显**：目前没有一个开源项目能同时搞定“阶段路由 + 安全边界 + 聊天解析 + 长期记忆”。你的规划正好填补了这个综合性缺口。

## 2. 需要修改与避坑的点（排雷指南）

根据 issue 反馈和竞品缺陷，你的新 Skill 在设计时必须绕开以下几个坑：

* **⚠️ 抛弃重度本地解密依赖**
* **反面教材**：`863401402/she-love-me`。它的 Issue 集中爆发在上游解密器失效、Windows 时间戳（秒与毫秒混用）崩溃上。
* **修改建议**：输入管线必须做轻。放弃强依赖微信本地 SQLite 数据库解密的方案。改用“多格式文本解析器”，支持用户直接复制粘贴文本、导出 Markdown/TXT，或者效仿 `ex-ai` 采用纯前端/本地的正则表达式进行说话人分离。


* **⚠️ 剔除伪科学与过度推断（Over-fitting）**
* **反面教材**：部分项目仅凭几句聊天记录就强行诊断对方的 MBTI 或是用占星学（如 `vedic-astro-skills`）算命。
* **修改建议**：建立“证据分级机制”。把“看到的客观事实（回复频率、字数）”与“主观推断（依恋类型）”严格分开。如果没有足够证据，允许系统输出 `insufficient_evidence`，而不是强行贴标签。


* **⚠️ 拒绝单一的“话术生成器”定位**
* **反面教材**：`replyher/love-reply-skill` 采用度低，且容易沦为低级的话术检索库。
* **修改建议**：回复生成必须带上“代价分析”。在给出一句回复前，必须列出发送的时机、可能的积极/消极反馈以及下一步对策。



## 3. 建议补充的核心功能

为了让这个 Skill 真正具有实操性和不可替代性，建议在架构中补充以下模块：

### A. 多模态与容错输入层 (Robust Input Layer)

必须具备一个健壮的适配器，支持：

* **格式自适应**：自动识别微信、QQ、短信等不同平台的复制粘贴格式。
* **语音与截图支持**：集成 OCR 或视觉模型能力，允许用户直接丢入聊天截图或语音转写的文本（响应 `she-love-me` issue #20 和 #21 的痛点）。

### B. 关系沙盒演练模式 (Roleplay Sandbox)

很多时候用户不仅需要“建议”，更需要“练习”。

* **功能设计**：引入一个隔离的交互模式，AI 根据历史记录模拟目标对象的语气，让用户亲自尝试发送消息。AI 作为 Coach 在旁边给予实时点评（指出边界感、需求感等问题）。

### C. 关系质量量化与安全预警 (RQI & Safety Guardrails)

* **量化指标**：引入关系质量指数（RQI），例如参考 `partner-skill`，通过数学模型化来评估关系动量，如计算公式 $RQI = \sum(w_i \times s_i) \times ACS\_modifier$，让情感分析有量化支撑。
* **安全阻断器**：植入针对 NPD（自恋型人格障碍）、煤气灯效应、冷暴力、PUA 的双阈值检测（字面特征+量化频率）。一旦触发，强制切断普通推进路由，转入安全与自救指南。

### D. 本地加密长期记忆 (Encrypted Local Journal)

* **功能设计**：由于亲密关系数据高度隐私，记忆模块绝不能上传云端。采用本地加密 JSON 或 SQLite 存储关系的“大事件（Milestones）”和“雷区”，在每次调用时作为 Context 注入。

## 5. 架构与落地建议

在技术落地上，这个项目非常适合封装成 Claude Code 的 CLI 插件，或者通过接入 DeepSeek 等 API 构建一个本地的终端脚手架。

在处理海量的聊天记录分析时，可以将文本挖掘技术应用到数据预处理环节，引入聚类模型来提炼长期关系中的话题走向和情绪周期。结合社会学与心理学的定性分析，能让 AI 的诊断更具学术支撑和信服力。而在最终的回复生成模块，扎实的散文与文学创作功底能够帮助你极大地调优 Prompt，让 AI 代拟的文案摆脱僵硬的“机器味”，显得真诚、灵动且充满分寸感。

考虑到聊天记录格式的多样性和极高的隐私敏感度，你打算优先支持哪种输入方式（比如：纯文本复制粘贴适配、网页端离线解析，还是直接处理本地导出的文档）？
