这份调查报告非常详实。根据提供的数据，现有的 `relationship-coach` 设计在市场上确实有需求，但当前开源生态中的项目能力高度碎片化，且部分项目存在严重的伦理和过度推断风险。

以下是为你整理的 Skill 审阅与修改补充报告：

# 关系教练 (Relationship Coach) Skill 审阅与功能补充报告

## 一、 现状痛点与架构修改建议

通过对现有的直接对照项目（如 `goutoujunshi`、`she-love-me`）的用户反馈和 Issue 进行审计，当前生态中存在以下显著痛点，需要在架构设计上重点修改：

1. **解决输入管线的脆弱性与格式限制**：现有应用高度依赖外部解密器，上游工具失效会导致整个流程中断；毫秒与秒时间戳混用经常导致运行崩溃；且用户迫切需要 Markdown 导出文件、语音消息转写和企业微信格式的输入支持。建议为该 Skill 编写一个健壮的本地输入层脚本，将平台导出、OCR 识别与时间戳规范化进行完全隔离。在通过 Claude Code 这一类命令行开发者工具进行配置和环境管理时，解耦输入管线能大幅减少外部依赖漂移带来的维护负担。


2. **规范证据分级以避免诊断越界**：许多项目会将冰冷的统计相关性（如回复频率、词云）直接武断地升级为人格诊断（如过度依赖 MBTI 与星座）或最终结局预测，导致给出过度自信甚至完全错误的危险建议。任何结论都必须有时间戳和原文锚点作为支撑，在结构化输出时应提供 `value`、`reason`、`evidence_level` 和 `observable_signals` 等高可读性字段，而非直接将原始 JSON 暴露给用户。



## 二、 需要补充的核心功能组合

新 Skill 的破局点并不在于创造新的恋爱理论或套路话术，而是将分散在各个仓库中的核心能力统一起来，形成一个安全的全生命周期关系支持系统：

1. **全生命周期阶段路由**：补充从单身追求、日常聊天、约会规划，一直到长期伴侣经营、投入失衡降级、冷战冲突修复，乃至安全退出的完整路由状态机。


2. **高风险过滤与双阈值安全边界**：补充对 NPD（自恋型人格）、PUA、煤气灯效应、间歇性强化和情感虐待的识别预警。一旦同时触发量化统计与文本特征的“双阈值”警报，系统必须立即中断普通恋爱指导，强制切换至危机分流与安全支持模式。


3. **隐私会话与长效记忆治理**：提供离线的长期关系日志功能，并在交互中落实严格的端侧加密、明确授权与随时遗忘（撤销/清空）机制。不应将真实伴侣“克隆”或“蒸馏”成可随时召唤操控的虚拟数字代理，而是建立仅供分析与复盘的安全加密档案。


4. **非暴力沟通的训练沙盒**：开发对话演练沙盒模块。当用户面临冲突或不知如何回复时，系统不应直接提供僵硬的套路话术，而是允许用户在沙盒中扮演自己，由 AI 模拟对方人格进行场景演练与客观的复盘评估。
