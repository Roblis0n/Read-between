## 结论

**普通恋爱咨询、聊天分析和消息代拟：行。作为可正式承诺“隐私安全、长期记忆可靠、危机处置完备、人格洞察有证据”的稳定技能：目前不行。**

它的主干设计是好的：安全优先、尊重拒绝、反操纵、事实/解释/未知分离、渐进加载和可执行输出都已经成形。当前真正拉低可信度的不是框架，而是若干内部冲突、无法保证的隐私承诺、未完成的记忆机制、伪科学表述和验证脚本的“看似通过”。先一次性修完下述高优先级问题，再对外称为完整技能更稳妥。

| 能力 | 当前判断 |
|---|---|
| 普通关系分析、追求决策、消息代拟 | 可用 |
| 聊天证据校准、拒绝与边界保护 | 基础良好，需消除固定阈值 |
| 星座/八字/MBTI | 只能作为明确标注的文化/娱乐性符号框架，当前事实化表述过多 |
| 长期记忆与隐私承诺 | 暂不可作为可靠能力宣传 |
| 暴力、自伤、勒索等危机场景 | 可做初步分流，不宜宣称处置完备 |

## 已经做得好的部分

1. `SKILL.md` 181 行，低于官方建议的 500 行上限；全部运行时参考文件均为一层直达引用，渐进加载结构正确。
2. “不预测成功率、不诊断人格、不绕过拒绝、不做数字分身、不自动发送消息”等边界清楚且有价值。
3. 聊天分析把原话、行为、替代解释、未知和验证动作分开，能明显降低读心与过度解读。
4. 消息代拟默认先给一条可直接使用的成品，符合结果导向。
5. 安全危机覆盖普通恋爱策略的优先级设计正确。

## 必须先修的高优先级问题

### P0-1：隐私说明包含无法保证或相互矛盾的承诺

`references/privacy-threat-model.md:7` 声称数据“不上传、不共享、不用于训练”，第 27 行又声称“所有分析和建议在本地完成”。Skill 本身不能替 Codex/模型服务保证这些平台级事实；“本地文件保存”也不等于“模型推理完全本地”。第 62 行还给身份证号、密码、私密影像、精确位置等“不可存储信息”保留了经确认后的例外，这是危险漏洞。

**应改：**只承诺 Skill 自己控制的行为；明确区分“本地文件写入”“模型处理”“外部工具调用”；密码、私密影像、身份凭证和精确位置设为绝对不保存；默认不主动建议建档，只有用户明确提出保存/召回/删除时才进入记忆流程。

### P0-2：证据注册表没有真正完成注册，人格层把符号体系写成了事实

`references/source-registry.md` 定义了来源 URL、日期和适用边界，但实际关键条目没有给出来源 URL。`references/personality-insight-layer.md:33` 的“太阳星座只占约 10%”、月亮星座更重要、行星周期影响关系氛围、五行反映性格、MBTI 认知功能栈是“精髓”等，均被写成事实陈述，和“不把类型学当证据”的总则冲突。

**应改：**星座与八字统一改写为“该传统体系内部如何解释”，不得写成现实因果或人格事实；删除无来源百分比和预测性表述；MBTI 四字母偏好、认知功能理论及其证据局限分开写；所有经验性关系主张补齐可核验来源、发布日期、最后核验日和适用人群。`agents/openai.yaml` 中“精通星座/八字/MBTI人格洞察”也应降调，避免误导与错误触发。

### P0-3：核心规则禁止固定阈值，参考文件却大量使用固定阈值

`SKILL.md:34` 明确禁止把回复速度、消息数或固定天数当普遍规律；但 `lifecycle-routing.md:57,94` 使用“已读不回 ≥2 次”“主动比例 >3:1”，`pursue-or-not.md:37,124` 使用“至少 2 个强信号”“接下来两周”，`pursuit-strategy.md:99` 使用“至少 2–3 次互动”，`early-dating.md:94` 使用“3 次以上约会”。这会让模型把启发式数字误当决策门槛。

**应改：**全部换成情境判断：是否反复出现、是否有解释或修复、是否提供替代时间、是否存在持续互惠、用户是否感到压力。确需数字时，只能标成“用户自己选择的观察窗口示例”，不得作为兴趣或关系阶段证据。

### P0-4：长期记忆目前是协议草案，不是完整可依赖的功能

`memory-protocol.md:14` 承诺会话结束后自动清除，第 19 行固定使用 `D:\Codex work\relationship-coach-data\`；但目录中只有验证脚本，没有实际的同意门禁、原子写入、索引更新、召回、过期、导出和删除实现。`validate_memory_store.ps1` 在数据根不存在时直接成功退出，记录校验失败后最终仍固定 `exit 0`；`validate_record.ps1` 的 `-Strict` 分支没有实际校验逻辑。

**应改：**二选一且不要折中：要么先从描述和自动路由中移除长期记忆能力；要么补齐平台无关的数据根、显式同意令牌、最小化写入、原子写入、删除/撤销、过期策略、索引一致性和失败回滚。明文保存高敏感关系数据不应成为默认方案。

### P0-5：危机分流方向正确，但缺少会改变安全结果的关键条件

`safety-abuse-and-crisis.md` 要求实时核验本地资源，这是对的，但没有明确的地区适配流程、受监控设备风险、即时危险分级、用户本人自伤与他人胁迫自伤的分支差异；“不要删除证据”也写得过于绝对，在设备被监控时可能增加暴露风险。

**应改：**先判断是否有即时危险，再以最少信息确认地区并实时核验资源；增加“设备可能被监控时优先使用安全设备/可信联系人”的条件；证据保存必须以“不增加现实危险”为前提；把家暴/跟踪、私密影像勒索、自伤风险、未成年人/权力差拆成清晰分支。普通权力差与已经存在强制控制也不应一概等同。

### P0-6：脚本名称和注释承诺的能力大于实际实现，容易制造假安全感

- `normalize_timestamps.ps1:106` 无论 `DefaultTimezone` 传什么都硬编码 `+08:00`，数值时间戳也未按目标时区转换；脚本输出只保留时间字段，不能算完整聊天规范化。
- `validate_chat_import.ps1` 注释称检查说话人映射，实际 schema 没有该必填项。
- `redact_transcript.ps1:57` 会把待脱敏真实姓名写到终端日志，且规则远不足以证明文本已安全去标识化。
- `validate_contract.ps1` 只做正则和存在性检查，不解析 YAML，也不检查参考文件中的失效路径。
- `detect_cross_relationship_leakage.ps1` 注释称检查同一人物跨关系复用，实际没有实现该检查，也不是访问控制机制。

**应改：**验证器统一“失败即非零退出”；使用真实 YAML/schema 校验；时间转换真正使用传入时区并保留原消息；说话人映射成为必填；脱敏日志不得回显原始 PII；无法保证彻底脱敏时输出“仍需人工复核”，不能输出安全完成的暗示。

## 次高优先级精进

1. **范围与内容不一致。** Frontmatter 明确承诺异地恋与复合，但运行时参考中没有完整模块；“全生命周期”与阶段 6–11 仅概要也有落差。要么补齐异地、复合/背叛后修复、分手恢复等直接引用，要么收窄描述。
2. **路由过重。** 当前要求每次都加载意图和生命周期，简单的“帮我回一句”也可能先做心理洞察。保留安全扫描为必经项，其余改为按歧义触发；简单代拟走快速路径。
3. **不应主动发现“里程碑”后推销记忆。** `SKILL.md:107` 的自动记忆判断与默认不记忆精神不一致；改为只有用户主动提出时才加载记忆协议。
4. **减少性别与价值观预设。** 大量使用“她”、邀请方应付款、同居不是试婚、伴侣关系必然优先于原生家庭等表述过于单一。改为中性称谓，并把付款、家庭优先级、同居目的、单偶/非单偶等设为需要了解的个人与文化选择。
5. **修正概念性绝对句。** “边界不是拒绝”不准确，边界完全可以包含拒绝；“醉酒中的同意不是同意”应准确区分饮酒与无法理解/自由选择的失能状态，同时明确法律因地区而异。
6. **去除硬编码路径。** `data-root.txt` 和 `past-wis-bridge.md` 固定到 `D:` 盘，当前技能实际位于 `F:` 盘，且不具备跨机器能力。改为相对路径、环境配置或按技能名调用 `past-wis`，缺失时明确降级。
7. **精简发现元数据。** Description 约 623 字符，虽未超过 1024 字符上限，但过长且容易在技能列表预算不足时被截断。前置核心触发词，把星座/记忆等次要能力后移或拆分。
8. **清理发布包。** `research-packet.json`、`research-report.md`、`plan.md`、`ARCHITECTURE.md` 均未被 `SKILL.md` 引用，合计约 856 KiB。研发资料应移到 Skill 目录外；本报告也应在整改完成、准备发布时一并归档到外部审查目录。

## 一次性整改顺序

1. 先统一安全、隐私、记忆三份契约，删除所有无法保证的承诺和敏感信息例外。
2. 把星座/八字改为传统符号视角，把 MBTI 改为有证据边界的偏好框架，并补齐来源注册。
3. 全局删除固定次数、比例和天数门槛，统一为互惠、修复、替代方案和持续模式。
4. 决定长期记忆是“真正实现”还是“暂时下线”，不要保留半实现状态。
5. 修正全部脚本的契约错位、硬编码、失败码和隐私日志。
6. 补齐或删减异地、复合、分手恢复等承诺范围；同时完成性别、关系形态和文化中性化。
7. 收紧 `SKILL.md` 与 `openai.yaml`，移走非运行时研发材料。

## 最终验收标准

- 不再出现平台级“绝不上传/不训练/完全本地”等 Skill 无法控制的承诺。
- 密码、私密影像、身份证明和精确位置无任何保存例外。
- 决策规则中不存在固定消息数、主动比例、约会次数或天数门槛。
- 每个经验性知识主张都有可核验来源；星座/八字不再以经验事实口吻呈现。
- 对外描述的每项能力都有对应运行时文件或确定性实现。
- 所有路径可配置且跨机器，不依赖固定盘符。
- 验证脚本不能在数据根缺失、记录失败或 schema 缺项时报告成功。
- 简单请求能直接给结果，高风险请求能稳定覆盖普通恋爱策略。

## 保留不动的核心

安全优先、尊重拒绝、反操纵、行为证据优先、事实/解释/未知分离、一条首选消息、明确下一步与退出条件——这些是该 Skill 最有价值的骨架，应保留并围绕它们做减法和加固。
